## <a id="s3-df-on-the-socket-for-pmtud"></a>§3, §4.1 — DF on the socket for PMTUD probes

Status: ✅ since 0.3.0 · [summary](../rfc-compliance.md#quic)

Original row: RFC 8899 §3, §4.1.

**Requirement.** DF on the socket for PMTUD probes.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- `EMSGSIZE` — skip one slot (counted with its size, `ksl_udp_emsgsize`, ksl ABI 7)
- Apple has no error queue (an unconnected socket gets no ICMP), Windows reports ICMP without MTU or quote (only `WSAEMSGSIZE` is used), NIO neither
- `KslDatagramIo` reports `caps.df`, and the search reaches 1452 on loopback (JVM Linux and macOS, Native Linux and macOS, Android).
- The portable NIO socket sets DF where the runtime can (`jdk.net.ExtendedSocketOptions.IP_DONTFRAGMENT`, JDK 19 and later, 0.2.1 — `NioDatagramIoTest.nioSetsDontFragmentWherePossible`) and keeps its datagrams within 1200 bytes: PMTUD is inactive there

**Tests that pin it.**

- `test_udp.c` `udp_df_probe_mode` (Linux and Apple), `udp_recverr_port_unreachable_keeps_socket`, `udp_ptb_ring`, `udp_emsgsize_counted` (Apple), `udp_recverr_local_emsgsize_queued`, `udp_recverr_ptb_parsed` and `udp_recverr_forged_ptb_keeps_sending` (Linux, in a user namespace, SKIP without one)
- `KslDatagramIoTest.negative_icmpPortUnreachableDoesNotKillTheSocket`
- `KslUdpSocketTest.grantedFlags`
- `KslDatagramIoTest.realUdpServerClient50MiBAccelerated`

**History.**

- 0.2.0: Apple — `IP_DONTFRAG`/`IPV6_DONTFRAG` (Darwin has no PMTUDISC modes)
- 0.2.0: Windows — `IP_DONTFRAGMENT`/`IPV6_DONTFRAG` plus `IP_MTU_DISCOVER`/`IPV6_MTU_DISCOVER = PROBE` where the system has it (Windows 10 1703+; verification on a Windows host pending)
- 0.3.0: Linux and Android also set `IP_RECVERR`/`IPV6_RECVERR` and drain the ICMP error queue, so an ICMP port or host unreachable never fails the receive and ICMP Packet Too Big messages reach the core as hints (`ksl_udp_take_ptb`)

**Peer interop notes.**

- `ksl_udp` (Linux, Android) — `IP_PMTUDISC_PROBE` + `IPV6_DONTFRAG`, not `_DO` (CVE-2024-53259 quic-go)

## <a id="s3-probing-black-holes-ptb-timers"></a>§3, §4.3, §4.6, §5.1.1 — probing, black holes, Packet Too Big, timers

Status: ✅ since 0.3.0 · [summary](../rfc-compliance.md#quic)

**Requirement.** The DPLPMTUD rules RFC 9000 §14.3 takes from this document, item by item.

**How it is met.**

- §3 item 7 and RFC 9000 §14.4 (probe loss is no congestion signal): probes are tracked for loss (`SentFrames.PMTU_PROBE`) but never counted toward the congestion window, and their loss reaches no controller; a PLPMTU raise does not raise the window either: `onMtuUpdate` of NewReno and CUBIC sets only the segment size and the minimum window (`NewReno.kt`, `Cubic.kt`), BBR recomputes its initial window only before anything was delivered (`Bbr.kt`) — `core.PmtudTest.probeLossNotCongestion` (a transfer during the search on a link that drops every probe: no congestion event), `.ccNotifiedOnMtuChange`
- §4.3 black-hole detection: three lost packets above 1200 bytes with no later full-size packet acknowledged, or two consecutive PTOs while an ack-eliciting packet above 1200 bytes is unanswered, fall back to 1200 and pause the search 60 s; a full-size packet acknowledged afterwards undoes the verdict (details in the [RFC 9000 §14 row](9000.md#s14-dplpmtud-mtu-1200-minimum)) — `core.PmtudTest.blackHoleFallsBackTo1200AndPauses60s`, `.congestionBurstDoesNotFallBack`, `.stalledPeerIsNotABlackHole`, `.unansweredSmallPacketsAreNotABlackHole`
- §4.6.1, §4.6.2 Packet Too Big validation: a PTB is a hint (`QuicConfig.pmtudIcmpHints`): it must quote one of the connection's packets on its active path (our ID or the path's peer ID), come for `path.remote` on that socket, claim a size the path sent more than, and leave at least 1200 bytes of payload; at or above the current size it ends the larger probes at once, below it starts confirmation probes of the current size, and only three lost ones lower the size; at most 64 PTBs a second per endpoint are examined — `core.PmtudTest.negative_ptbWithForeignCidIgnored`, `.negative_ptbBelowQuicMinimumIgnored`, `.negative_ptbNeverLowersMtuWithoutConfirmation`, `.ptbQuotingAProbeEndsThatSizeAtOnce`, `.ptbConfirmedByLostProbesLowersToPtbSize`, `.negative_ptbFloodIsRateLimited`
- §5.1.1 constants: MAX_PROBES 3 (a size is given up after three lost probes, `Pmtud.maxProbes`), PMTU_RAISE_TIMER 600 s (a new search 600 s after the last one ended, `Pmtud.research`); a probe is declared lost by loss detection (RFC 9002), which takes the place of PROBE_TIMER — `core.PmtudTest.atMostThreeLostProbesPerSize`, `.researchAfter600s`
