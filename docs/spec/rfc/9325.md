# RFC 9325 — Recommendations for Secure Use of TLS and DTLS

Details of the rows of the [RFC compliance summary](../rfc-compliance.md) for this document. Each section gives the requirement, how Kuicksilver meets it (with the files), the tests that pin it, its history, notes on peers and the open items. Status: ✅ met · 🔶 feature subset · ⬜ planned · ❌ not planned; "since" is the release from which the current behaviour holds (history below and in [CHANGELOG.md](../../../CHANGELOG.md)).

## <a id="s3-5-ems"></a>§3.5 — TLS 1.2 implementations support Extended Master Secret

Status: ✅ since 0.2.1 · [summary](../rfc-compliance.md#tls)

**Requirement.** TLS 1.2 implementations MUST support the extended master secret extension (§3.5).

**How it is met.** Recorded in the row [RFC 5246 (obsoleted by RFC 9846; TLS 1.2 itself stays as written there)](5246.md#tls-1-2-tcp-explicit-only):

- only with an explicit `TlsVersions`, only with EMS (RFC 7627 §5.2: an endpoint that does not interoperate with legacy peers SHOULD abort the handshake, and ksl's refusal is that local policy; the extension is named `extended_main_secret` by RFC 9846 App. D, which leaves RFC 7627's rules in place; RFC 9325 §3.5: TLS 1.2 implementations MUST support it)

## <a id="s4-4-aead-limits"></a>§4.4 — AEAD record limits

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#tls)

**Requirement.** SHOULD respect the AEAD limits, RECOMMENDED 2^24.5 records for AES-GCM (§4.4).

**How it is met.** Recorded in the row [RFC 5246 (obsoleted by RFC 9846; TLS 1.2 itself stays as written there)](5246.md#tls-1-2-tcp-explicit-only):

- RFC 9325 §4.4 (SHOULD, RECOMMENDED limit 2^24.5 records for AES-GCM): with no KeyUpdate and no renegotiation a connection ends before its keys reach the AEAD's limit (2^24.5 records for AES-GCM, none for ChaCha20-Poly1305), with internal_error where an alert can be sent (a client) — C `tcp_record_limits_per_cipher`

## <a id="s7-5-revocation"></a>§7.5 — certificate revocation

Status: ⬜ (not scheduled) · [summary](../rfc-compliance.md#tls)

**Requirement.** Certificate revocation checking (§7.5); planned with the OCSP row of RFC 6960.

**How it is met.** Recorded in the row [RFC 6960 / 6961 (6961 obsoleted by RFC 9846: `status_request_v2` is `ocsp_multi_RESERVED`)](6960.md#ocsp-stapling):

- Linux Native and every other `TrustConfig` mode use the OpenSSL verifier without CRLs or OCSP — a known limitation (RFC 9325 §7.5).
