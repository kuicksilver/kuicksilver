## <a id="s5-2-ems-required"></a>§5.2 — Extended Master Secret required for TLS 1.2

Status: ✅ since 0.2.1 · [summary](../rfc-compliance.md#tls)

**Requirement.** A TLS 1.2 endpoint that does not interoperate with legacy peers SHOULD abort a handshake without the extension (§5.2).

**How it is met.** Recorded in the row [RFC 5246 (obsoleted by RFC 9846; TLS 1.2 itself stays as written there)](5246.md#tls-1-2-tcp-explicit-only):

- over TCP only, with `TlsVersions.Tls12And13` (the Ktor client's default since 0.3.0, explicit elsewhere), only with EMS (RFC 7627 §5.2: an endpoint that does not interoperate with legacy peers SHOULD abort the handshake, and ksl's refusal is that local policy; the extension is named `extended_main_secret` by RFC 9846 App. D, which leaves RFC 7627's rules in place; RFC 9325 §3.5: TLS 1.2 implementations MUST support it)

**Tests that pin it.**

- C `tcp_tls12_profile_and_ems` (EMS is negotiated over TLS 1.2; a client without it is refused by the server with
  `KSL_E_EMS_REQUIRED` and `handshake_failure`, and a server without it is refused by the client before its Finished, also
  by a client that verifies nothing), `ServerTls12JdkClientTest.negative_jdkTls12ClientWithoutEmsRefused` (the JDK's TLS 1.2
  client), `ClientTls12KslServerTest.negative_tls12ServerWithoutEmsIsRefused` (the Ktor client against a TLS 1.2 server
  whose ServerHello comes without the extension)
