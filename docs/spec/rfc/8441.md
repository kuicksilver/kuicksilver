# RFC 8441 — Bootstrapping WebSockets with HTTP/2

Details of the rows of the [RFC compliance summary](../rfc-compliance.md) for this document. Each section gives the requirement, how Kuicksilver meets it (with the files), the tests that pin it, its history, notes on peers and the open items. Status: ✅ met · 🔶 feature subset · ⬜ planned · ❌ not planned; "since" is the release from which the current behaviour holds (history below and in [CHANGELOG.md](../../../CHANGELOG.md)).

## <a id="websocket-over-http-2"></a>WebSocket over HTTP/2 (Extended CONNECT)

Status: ⬜ planned for 0.3.0 · [summary](../rfc-compliance.md#http)

**Requirement.** §3: the SETTINGS_ENABLE_CONNECT_PROTOCOL parameter, "The value of the parameter MUST be 0 or 1"; §4:
the Extended CONNECT method with the `:protocol` pseudo-header field; §5: WebSockets over a single HTTP/2 stream.

**Recorded status.** ⬜ planned for 0.3.0 ([roadmap](../../roadmap.md), ADR-0017: the owner's scope of 2026-11-04 puts
the whole HTTP/2 section, RFC 8441 included, into 0.3.0); not offered yet.

**What holds now.**

- Neither HTTP/2 engine offers WebSockets over HTTP/2: the server never sends SETTINGS_ENABLE_CONNECT_PROTOCOL, so a
  request with `:protocol` is malformed (§3: a client MUST NOT use it without the setting; RFC 9113 §8.1.1), and the
  client offers only `http/1.1` in ALPN for a WebSocket (as OkHttp does) — see [RFC 9113](9113.md#http-2) and
  [§3.2, §3.3 — starting HTTP/2 (client)](9113.md#s3-2-starting-http-2-client).
- §3: a SETTINGS_ENABLE_CONNECT_PROTOCOL value above 1 is a connection error PROTOCOL_ERROR
  (`H2ConnectionCore.frames.kt`).
- §4: the codec checks an Extended CONNECT the way the HTTP/3 one does for RFC 9220: `:protocol` only with the setting,
  only on CONNECT, with `:scheme`, `:path` and `:authority`, and as a token, the form of a name from the HTTP Upgrade
  Token Registry (RFC 9110 §16.7; `message/H2Fields.kt`) — `message.H2MessagesTest.negative_extendedConnectNeedsTheSetting`,
  `.negative_extendedConnectProtocolIsAToken` (0.3.0).

**Open items.**

- WebSockets over HTTP/2 in both Ktor engines (§5), planned for 0.3.0.
