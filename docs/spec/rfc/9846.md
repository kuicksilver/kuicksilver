# RFC 9846 — The Transport Layer Security (TLS) Protocol Version 1.3 (obsoletes RFC 8446)

Details of the rows of the [RFC compliance summary](../rfc-compliance.md) for this document. Each section gives the requirement, how Kuicksilver meets it (with the files), the tests that pin it, its history, notes on peers and the open items. Status: ✅ met · 🔶 feature subset · ⬜ planned · ❌ not planned; "since" is the release from which the current behaviour holds (history below and in [CHANGELOG.md](../../../CHANGELOG.md)).

## <a id="s8-0-rtt-anti-replay"></a>§8, §4.3.10 — 0-RTT anti-replay

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#quic)

Original row: RFC 9846 §8, §4.3.10.

**Requirement.** 0-RTT anti-replay.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- OpenSSL's ticket-age freshness (±10 s), a per-server replay register keyed by the ticket identity (two rotating 20 s halves, 1 MiB, fails closed), single-use client tickets

**Tests that pin it.**

- `core.ZeroRttTest.negative_0rttReplayRejected`, `tls.QuicEarlyDataTest.negative_0rttReplayRejected`, `endpoint.ZeroRttReplayRegisterTest.*`

## <a id="tls-1-3"></a>(obsoletes RFC 8446) — TLS 1.3

Status: ✅ since 0.2.1 · [summary](../rfc-compliance.md#tls)

Original row: RFC 9846 (obsoletes RFC 8446).

**Requirement.** TLS 1.3.

**Recorded status.** ✅ 0.2.0, against RFC 8446 (section numbers here are RFC 9846's: the handshake sections moved one down, §4.1 → §4.2 … §4.6 → §4.7; appendix D → E, E → F); §4.2.2/§4.2.3 ✅ 0.2.1: a hello whose `legacy_version` is not 0x0303 is refused with `protocol_version` on both sides (OpenSSL accepted 0x0301/0x0302; the server in the ClientHello callback, the client by disabling every version before OpenSSL checks the ServerHello) — C `tcp_legacy_version_must_be_0303`; §4.7.3 ✅ 0.2.1: the KeyUpdate epoch never passes 2^48−1 updates (after the last allowed one no KeyUpdate of ours, a peer's `update_requested` flag ignored (SHOULD), the last keys used until their §5.5 record limit, where the session ends; received updates are not counted) — C `tcp_key_update_epoch_is_bounded`; no second `update_requested` until the peer's KeyUpdate (a further request goes out as `update_not_requested`) — C `tcp_second_update_requested_waits_for_the_peer`; §6, §6.2 ✅ 0.2.1: `general_error` (117) is named, a TLS 1.3 error alert at level warning is reported by its code — `AlertNameTest.alertNames`; App. C.4 ✅ 0.2.1 (SHOULD): six tickets per TCP full handshake (the appendix's example: "a web browser using HTTP/1.1 might open six connections to a server"), one per resumption, six kept per origin by the client, each used once — C `tcp_client_keeps_every_ticket`, `SessionCacheTest.severalTicketsPerOrigin`, `SessionResumptionTest.sixConnectionsResumeFromOneFullHandshake`; App. E.5: TLS 1.0 and 1.1 refused even at the ksl level — C `tcp_default_versions_and_tls12_profile`; §6.1 🔶 0.2.1: a TCP connection whose application stream failed never ends with `close_notify`; a TLS 1.3 server and a TLS 1.2 client send the fatal alert internal_error after what they had sent (`ksl_tcp_abort`: OpenSSL 3.5 sends an alert on an established connection only when building a handshake message fails, so ksl fails a NewSessionTicket, or a TLS 1.2 renegotiation ClientHello before any of it is written); open: a TLS 1.3 client and a TLS 1.2 server (no such message); §5.5 (MUST; RFC 8446 said SHOULD) ✅ 0.2.1: over TCP the sending key is updated (KeyUpdate) before the negotiated AEAD's limit: every 2^23 records under AES-GCM (limit 2^24.5), 2^22 under AES-CCM (limit 2^23, RFC 9147 App. B.1, as RFC 9846 gives none), none under ChaCha20-Poly1305 (no limit); a session whose KeyUpdate cannot go out ends before the limit, with internal_error where an alert can be sent (OpenSSL sends KeyUpdate only on request; TLS 1.2 has none) — C `tcp_record_limits_per_cipher`

**Tests that pin it.**

- through OpenSSL 3.5
- `TlsConnection` (TCP) and `QuicTlsSession`
- `TlsConnectionTest`, `QuicHandshakeTest`, C `tcp_key_update_before_record_limit`, `tcp_abort_sends_internal_error`, `TlsConnectionTest.negative_aFailedServerOutputSendsInternalError`, `TlsFailedStreamTest.negative_aFailedTlsStreamEndsWithInternalError`
