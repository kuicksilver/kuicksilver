## <a id="s2-2-decoder"></a>§2.2, §3.2, §4.3–4.5 — decoder

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.2, §3.2, §4.3–4.5.

**Requirement.** Decoder: dynamic table, encoder stream instructions (including ones split by the transport), Required Insert Count with wrapping, Base, five field line representations, blocked streams, Section Acknowledgment / Stream Cancellation / Insert Count Increment.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- a capacity above the advertised one → `QPACK_ENCODER_STREAM_ERROR`, a reference to an evicted entry or beyond the RIC → `QPACK_DECOMPRESSION_FAILED`
- §4.5.4/§4.5.6/§7.1.3, the never-indexed ('N') bit: "an intermediary MUST use a literal representation" to forward a field
  line it received with the bit set. The decoder reads the bit and does not pass it on (`Http3Headers` carries names and
  values only), so it does not apply to Kuicksilver, which is no intermediary: neither engine forwards a field section,
  and an application that builds one from both engines is the intermediary. What our encoder sends is never indexed for
  `authorization`, `proxy-authorization`, `cookie` and `set-cookie` (encoder row), whatever the bit said when the
  field arrived

**Tests that pin it.**

- `qpack.RfcAppendixBTest.appendixBInSequence` (appendix B.1–B.5 byte for byte), `qpack.QpackDecoderTest.*` (review pins: `negativeBaseFails`, `impossibleEncodedInsertCountFails`, `staticIndexOutOfRangeInFieldLineFails`, `staticIndexOutOfRangeOnEncoderStreamFails`, `insertLargerThanCapacityFails`, `encoderStreamReferenceToEvictedEntryFails`), `qpack.QpackEncoderTest.zeroInsertCountIncrementIsError`, `qpack.PrimitivesTest.paddingLongerThan7BitsRejected`, `qpack.DynamicTableTest.*`

## <a id="s7-4-split-encoder-stream-instructions"></a>§7.4 — split encoder-stream instructions

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §7.4.

**Requirement.** An encoder-stream instruction split by the transport is reassembled in linear time: its length is known from the string literal's prefix, bytes are appended until it is complete, the parser never re-reads the accumulated prefix per fragment (before 0.2.0: a 60 KB literal fed byte by byte cost ≈ 1.8 GB of copying).

**Recorded status.** ✅ 0.2.0

**Tests that pin it.**

- `qpack.QpackDecoderTest.negative_qpackFragmentedEncoderInstructionLinear`

## <a id="s2-1-2-streams-in-the-connection"></a>§2.1.2, §4.2, §4.4 (in the connection) — streams in the connection

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.1.2, §4.2, §4.4 (in the connection).

**Requirement.** Encoder and decoder streams.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- encoder instructions go out before the block that references them
- a blocked section waits for inserts, Section Acknowledgment comes after decoding
- a stream reset by the peer while blocked gets a Stream Cancellation, and so does one reset by the peer, or abandoned by the reader, after its first HEADERS while the body or trailers are pending (review: only the blocked case, `abort`, 425/431 and `cancel` sent it); a client response abandoned because the request's own trailers were refused (above the server's limit) gets one too, once its body pump stopped, so response trailers blocked at that moment give their blocked-stream slot back
- a 17th blocked stream with 16 advertised → `QPACK_DECOMPRESSION_FAILED`
- by default (0/0) the dynamic table is not used

**Tests that pin it.**

- `runtime.QpackDynamicTest.*` (including `negative_qpackBlockedStreams`, `blockedHeaderDecodedAfterLateInsert`), `runtime.QpackStreamCancellationTest.bodyEndedByResetOrConsumerCancelSendsCancellation`, `.refusedRequestTrailersCancelBlockedResponseTrailers`

## <a id="s2-1-encoder"></a>§2.1, §4.3, §4.5, §7.1 — encoder

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.1, §4.3, §4.5, §7.1.

**Requirement.** Encoder: static only until the peer's SETTINGS.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- capacity = min(peer, `encoderMaxTableCapacity` 4096)
- blocked streams ≤ min(peer, 100)
- unacknowledged sections ≤ 1000 (`MAX_OUTSTANDING_SECTIONS`): above the ceiling sections go without dynamic references until the peer acknowledges, the number of blocking streams is counted without walking all sections on every encode (review)
- does not evict unacknowledged entries or entries with open references
- never-index for `authorization`/`proxy-authorization`/`cookie`/`set-cookie`
- parsing of the peer's decoder stream (an ack of an unknown stream, an increment beyond the inserts → `QPACK_DECODER_STREAM_ERROR`)

**Tests that pin it.**

- `qpack.QpackEncoderTest.*` (including `negative_qpackUnackedSectionsCapped`), `qpack.QpackRoundTripTest.gridRoundTrip` (grid capacity {0, 256, 4096} × blocked {0, 1, 16} × ACK {immediately, delayed, never}, §9.1)

## <a id="s2-1-3-encoder-flow-control"></a>§2.1.3 — encoder instructions within flow-control credit

Status: ✅ since 0.3.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.1.3.

**Requirement.** "To avoid deadlocks, an encoder SHOULD NOT write an instruction unless sufficient stream and connection
flow-control credit is available for the entire instruction."

**Recorded status.** ✅ 0.3.0

**How it is met.**

- `QpackRuntime.encode` asks the encoder stream's send credit first (`QuicStream.sendCredit`, internal API: the smaller of
  the stream's and the connection's credit, less what the stream already holds unsent) and passes it to
  `QpackEncoder.encode` as the budget of the section's instructions: an insert whose whole instruction does not fit is
  not made, and its field goes as a literal (or a reference to what the table already holds). Without an encoder stream
  yet the budget is 0, and with a peer table capacity of 0 (no insert possible) the credit is not asked at all. The
  credit is an approximation on the safe side for the stream and close to it for the connection: it subtracts only
  the encoder stream's own unsent bytes, not those other streams hold against the connection's credit. Before 0.3.0
  inserts were written whatever the credit, under the encoder's lock.

**Tests that pin it.**

- `qpack.QpackEncoderTest.insertsStayWithinTheEncoderStreamCredit`, `runtime.QpackRuntimeTest.encoderCreditIsAskedOnlyWhenAnInsertIsPossible`, `kuicksilver-quic` `stream.BlockedFramesTest.sendCreditIsTheSmallerCreditLessUnsentData`

## <a id="s2-2-1-blocked-sections-in-the-window"></a>§2.2.1 — blocked sections stay in the flow-control window

Status: ✅ since 0.3.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.2.1.

**Requirement.** "While blocked, encoded field section data SHOULD remain in the blocked stream's flow-control window."

**Recorded status.** ✅ 0.3.0

**How it is met.**

- With blocked streams allowed (`qpackBlockedStreams` > 0, which `enableQpackDynamicTable()` sets), a request stream is
  read with its transport input bounded by a stream offset (`QuicStream.readAhead`, internal API, set from the reader's
  position and kept however the bytes before it are read: what the transport takes from a stream leaves its
  flow-control window): a frame header up to 3 bytes on (a type and a length below 16384 in one pull; past a HEADERS
  frame's header that is at most the start of its Required Insert Count prefix, read first anyway), a DATA or unknown
  frame up to its end, also when its payload arrives and is read in pieces, so nothing of a following field section
  is taken with it. A HEADERS payload's encoded Required Insert Count (§4.5.1.1) is then read byte by byte; a section
  that needs
  inserts not yet received counts as blocked there (`QpackRuntime.awaitInserts`, the same budget and Stream Cancellation
  as before) and waits, its other bytes left in the transport, so the peer gets no credit back for them. Before 0.3.0
  the whole payload was read first, up to 2 × `maxFieldSectionSize` per blocked stream held off the window.
- A WebTransport stream that arrives as a bidirectional request stream gets the usual read-ahead back once its first
  frame type says what it is: it carries no field section (`WebTransportStreamsTest.webTransportStreamsKeepTheUsualReadAheadWithTheDynamicTable`).
- Without blocked streams (the default) a section that would block is a QPACK_DECOMPRESSION_FAILED, and streams keep the
  default read-ahead.

**Tests that pin it.**

- `runtime.QpackDynamicTest.blockedSectionStaysInTheStreamWindow`, `.blockedTrailersAfterDataInPiecesStayUnread`, `kuicksilver-quic` `api.ReadAheadTest.readsInPiecesTakeNothingPastTheLimit`, `.blockedHeaderDecodedAfterLateInsert`, `.resetBlockedStreamSendsCancellation`, `.negative_qpackBlockedStreams`
