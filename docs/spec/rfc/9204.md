## <a id="s2-2-decoder"></a>§2.2, §3.2, §4.3–4.5 — decoder

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.2, §3.2, §4.3–4.5.

**Requirement.** Decoder: dynamic table, encoder stream instructions (including ones split by the transport), Required Insert Count with wrapping, Base, five field line representations, blocked streams, Section Acknowledgment / Stream Cancellation / Insert Count Increment.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- a capacity above the advertised one → `QPACK_ENCODER_STREAM_ERROR`, a reference to an evicted entry or beyond the RIC → `QPACK_DECOMPRESSION_FAILED`

**Tests that pin it.**

- `qpack.RfcAppendixBTest.appendixBInSequence` (appendix B.1–B.5 byte for byte), `qpack.QpackDecoderTest.*` (review pins: `negativeBaseFails`, `impossibleEncodedInsertCountFails`, `staticIndexOutOfRangeInFieldLineFails`, `staticIndexOutOfRangeOnEncoderStreamFails`, `insertLargerThanCapacityFails`, `encoderStreamReferenceToEvictedEntryFails`), `qpack.QpackEncoderTest.zeroInsertCountIncrementIsError`, `qpack.PrimitivesTest.paddingLongerThan7BitsRejected`, `qpack.DynamicTableTest.*`

## <a id="s7-4-split-encoder-stream-instructions"></a>§7.4 — split encoder-stream instructions

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §7.4.

**Requirement.** An encoder-stream instruction split by the transport is reassembled in linear time: its length is known from the string literal's prefix, bytes are appended until it is complete, the parser never re-reads the accumulated prefix per fragment (before 0.2.0: a 60 KB literal fed byte by byte cost ≈ 1.8 GB of copying).

**Recorded status.** ✅ 0.2.0

**Tests that pin it.**

- `qpack.QpackDecoderTest.negative_qpackFragmentedEncoderInstructionLinear`

## <a id="s2-1-2-streams-in-the-connection"></a>§2.1.2, §4.2, §4.4 (in the connection) — streams in the connection

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.1.2, §4.2, §4.4 (in the connection).

**Requirement.** Encoder and decoder streams.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- encoder instructions go out before the block that references them
- a blocked section waits for inserts, Section Acknowledgment comes after decoding
- a stream reset by the peer while blocked gets a Stream Cancellation, and so does one reset by the peer, or abandoned by the reader, after its first HEADERS while the body or trailers are pending (review: only the blocked case, `abort`, 425/431 and `cancel` sent it)
- a 17th blocked stream with 16 advertised → `QPACK_DECOMPRESSION_FAILED`
- by default (0/0) the dynamic table is not used

**Tests that pin it.**

- `runtime.QpackDynamicTest.*` (including `negative_qpackBlockedStreams`, `blockedHeaderDecodedAfterLateInsert`), `runtime.QpackStreamCancellationTest.bodyEndedByResetOrConsumerCancelSendsCancellation`

## <a id="s2-1-encoder"></a>§2.1, §4.3, §4.5, §7.1 — encoder

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 9204 §2.1, §4.3, §4.5, §7.1.

**Requirement.** Encoder: static only until the peer's SETTINGS.

**Recorded status.** ✅ 0.2.0

**How it is met.**

- capacity = min(peer, `encoderMaxTableCapacity` 4096)
- blocked streams ≤ min(peer, 100)
- unacknowledged sections ≤ 1000 (`MAX_OUTSTANDING_SECTIONS`): above the ceiling sections go without dynamic references until the peer acknowledges, the number of blocking streams is counted without walking all sections on every encode (review)
- does not evict unacknowledged entries or entries with open references
- never-index for `authorization`/`proxy-authorization`/`cookie`/`set-cookie`
- parsing of the peer's decoder stream (an ack of an unknown stream, an increment beyond the inserts → `QPACK_DECODER_STREAM_ERROR`)

**Tests that pin it.**

- `qpack.QpackEncoderTest.*` (including `negative_qpackUnackedSectionsCapped`), `qpack.QpackRoundTripTest.gridRoundTrip` (grid capacity {0, 256, 4096} × blocked {0, 1, 16} × ACK {immediately, delayed, never}, §9.1)
