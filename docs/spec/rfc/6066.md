Status: ✅ met · 🔶 feature subset or accepted deviation · ⬜ planned · ❌ not planned; "since" is the release from which the current behaviour holds (history below and in [CHANGELOG.md](../../../CHANGELOG.md)).

## <a id="sni"></a>(updated by RFC 9846 §4.5.1.1, OCSP) — SNI

Status: ✅ since 0.3.0 (TCP since 0.2.1) · [summary](../rfc-compliance.md#tls)

Original row: RFC 6066 (updated by RFC 9846 §4.5.1.1, OCSP).

**Requirement.** SNI.

Quoted: "MUST NOT accept the request to resume the session if the server_name extension contains a different name".

**Recorded status.** ✅ 0.2.0

**How it is met.**

- the client sends `serverName`
- the server — `sniSelector` with a pause (`ServerTlsOverride`), over TCP and (0.3.0) QUIC: the QUIC handshake pauses at
  `DriveResult.WantSni`, the endpoint runs the selector off the connection's loop and applies its choice
  (`QuicTlsSession.selectSni`, `resumeSni`); the chosen identity's chain, key, client-certificate policy, trust and staple
  answer the ClientHello. `ksl` keeps a QUIC session's TLS 1.3 floor, middlebox compatibility mode off (RFC 9001 sections
  4.2, 8.4) and `max_early_data_size` sentinel (RFC 9001 section 4.6.1) when it applies an override's settings
  (`ksl_ctx_apply_to_ssl`)
- §3 "If the server understood the ClientHello extension but does not recognize the server name, the server SHOULD take
  one of two actions: either abort the handshake by sending a fatal-level unrecognized_name(112) alert or continue the
  handshake": `null` from the selector for a name aborts with the fatal alert (QUIC: CRYPTO_ERROR 0x170, RFC 9001 section
  4.8); no warning-level alert is ever sent ("NOT RECOMMENDED")
- RFC 9846 §9.2 "Servers requiring this extension SHOULD respond to a ClientHello lacking a "server_name" extension by
  terminating the connection with a "missing_extension" alert" (0.3.0): a server without a default identity whose
  selector has nothing for a ClientHello without SNI sends `missing_extension` (109; QUIC 0x16d). `ksl` sends it once TLS
  1.3 is chosen (`server_name_cb`): OpenSSL maps an alert raised in the ClientHello callback with the TLS 1.2 table, where it
  becomes `handshake_failure`; a TLS 1.2 handshake gets `handshake_failure` (TLS 1.2 has no such alert)
- RFC 9846 §4.7.1 (RFC 8446 §4.6.1): a ticket resumes only under the leaf certificate it was issued under, so a
  ticket of one identity is never resumed, nor its 0-RTT accepted, under another the selector chose for the same name; a
  QUIC override with client certificates issues no ticket and accepts no 0-RTT
- RFC 9846 §4.7.1, client: clients "SHOULD only resume if the SNI value matches the one used in the original session"
  (0.3.0): `ksl_ssl_set_session` refuses a session of another server name (case-insensitive; no name only with no name),
  so `QuicTlsSession.resume` returns false and a TCP client runs a full handshake; a case variant resumes without 0-RTT,
  which OpenSSL's client checks byte for byte
- RFC 9846 §4.7.1 "On resumption, if reporting an SNI value to the calling application, implementations MUST use the
  value sent in the resumption ClientHello": `ClientHelloInfo.serverName` and `sniSelectedFor` are the current
  ClientHello's
- §3 resumption (0.2.1; RFC 9846 §4.3.11 makes this binding optional for TLS 1.3, ksl keeps it, and TLS 1.2 tickets need it): a server "MUST NOT accept the request to resume the session if the server_name extension contains a different name" — every ticket ksl issues (TCP and QUIC) carries a tag of the ClientHello's host name, and a ticket offered under another name, under no name, or from before names were bound runs a full handshake and gets a new ticket (OpenSSL compares no name on a TLS 1.3 resumption)
- the tag is SHA-256 of the name in ASCII lower case, so `a.test` and `A.TEST` share a ticket, as DNS names compare case-insensitively (RFC 4343)
- §3 acknowledgement (0.2.1): a server that used the name answers with an empty `server_name` (EncryptedExtensions in TLS 1.3, the ServerHello of a full TLS 1.2 handshake, none on a TLS 1.2 resumption)

**Peer interop notes.**

- §3: an IP literal is never sent in `server_name` — SNI is taken from `serverName` and omitted if it is an IP, even when the reference identity is set by `ExpectedName` (native-tls review)
