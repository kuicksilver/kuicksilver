## <a id="sni"></a>(updated by RFC 9846 §4.5.1.1, OCSP) — SNI

Status: ✅ since 0.2.1 · [summary](../rfc-compliance.md#tls)

Original row: RFC 6066 (updated by RFC 9846 §4.5.1.1, OCSP).

**Requirement.** SNI.

Quoted: "MUST NOT accept the request to resume the session if the server_name extension contains a different name".

**Recorded status.** ✅ 0.2.0

**How it is met.**

- the client sends `serverName`
- the server — `sniSelector` with a pause (`ServerTlsOverride`), TCP only (for QUIC — `TlsException.Config`)
- §3 resumption (0.2.1; RFC 9846 §4.3.11 makes this binding optional for TLS 1.3, ksl keeps it, and TLS 1.2 tickets need it): a server "MUST NOT accept the request to resume the session if the server_name extension contains a different name" — every ticket ksl issues (TCP and QUIC) carries a tag of the ClientHello's host name, and a ticket offered under another name, under no name, or from before names were bound runs a full handshake and gets a new ticket (OpenSSL compares no name on a TLS 1.3 resumption)
- the tag is SHA-256 of the name in ASCII lower case, so `a.test` and `A.TEST` share a ticket, as DNS names compare case-insensitively (RFC 4343)
- §3 acknowledgement (0.2.1): a server that used the name answers with an empty `server_name` (EncryptedExtensions in TLS 1.3, the ServerHello of a full TLS 1.2 handshake, none on a TLS 1.2 resumption)

**Tests that pin it.**

- `TlsServerTest.negative_unrecognizedSniFatal`, `.noSniUsesDefaultIdentity`, `QuicHandshakeTest.sniSelectorIsConfigErrorForQuic`, C `test_tcp.c` `test_sni_pause`, `TlsServerTest.ipServerNameNeverSentAsSni`, C `tcp_ticket_bound_to_server_name`, `tcp_server_acknowledges_server_name`

**Peer interop notes.**

- §3: an IP literal is never sent in `server_name` — SNI is taken from `serverName` and omitted if it is an IP, even when the reference identity is set by `ExpectedName` (native-tls review)
