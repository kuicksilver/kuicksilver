# RFC 1928/1929 — SOCKS Protocol Version 5 (RFC 1928) and Username/Password Authentication for SOCKS V5 (RFC 1929)

Details of the rows of the [RFC compliance summary](../rfc-compliance.md) for this document. Each section gives the requirement, how Kuicksilver meets it (with the files), the tests that pin it, its history, notes on peers and the open items. Status: ✅ met · 🔶 feature subset · ⬜ planned · ❌ not planned; "since" is the release from which the current behaviour holds (history below and in [CHANGELOG.md](../../../CHANGELOG.md)).

## <a id="s3-socks5-client"></a>§3–§6 (client) — SOCKS5 client

Status: 🔶 since 0.3.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 1928 §3–§6 (client).

**Requirement.** SOCKS5 CONNECT only (no BIND, no UDP ASSOCIATE, no SOCKS4): method negotiation offering "no authentication" and, with credentials, username/password.

**Recorded status.** 🔶 0.3.0

**How it is met.**

- a name as ATYP 3 for the proxy to resolve (`ProxyBuilder.socks`), address literals as ATYP 1/4
- the reply's bound address read with its length checked and dropped
- a reply other than "succeeded" → `ProxyException(replyCode = REP)`, an unknown ATYP, a non-SOCKS5 version or an unoffered method → `ProxyException` before any TLS
- every step under the connect timeout

**Tests that pin it.**

- `h1.Socks5Test.*`, `ClientSocksProxyTest.httpsThroughSocks5`, `.plainHttpThroughSocksUsesOriginForm`, `.negative_socksReplyFailsTheRequest`

**Open items.** See the roadmap ([docs/roadmap.md](../../roadmap.md)).

## <a id="username-password"></a>RFC 1929 — username/password

Status: 🔶 since 0.3.0 · [summary](../rfc-compliance.md#http)

Original row: RFC 1929.

**Requirement.** Username/password: offered only with credentials, sent only when the proxy picks method 02.

**Recorded status.** 🔶 0.3.0

**How it is met.**

- the reply's VER is 1 or 5 (§2 defines the reply as `VER STATUS` with VER X'01' and gives the client no rule for another value; some proxies answer with the SOCKS version, 5) (never to a proxy that chose "no authentication")
- a rejection → `ProxyException` naming the proxy, not the credentials

**Tests that pin it.**

- `h1.Socks5Test.negative_socksCredentialsNotSentWhenServerChoosesNoAuth`, `.negative_socksAuthRejected`, `.negative_socksOverlongCredentialsRejected`, `.negative_socksEmptyPasswordRejected`, `ClientSocksProxyTest.socks5UsernamePassword`, `.negative_socks5ProxyWithAnEmptyPasswordIsAConfigurationError`, `ProxyResolverTest.negative_socks5UrlWithAnEmptyPasswordFails`

**Peer interop notes.**

- user 1–255 and password 1–255 bytes (§2: PASSWD is 1 to 255 octets; curl and Go send an empty password as PLEN 0 anyway), else `IllegalArgumentException` before anything is sent, and for the password already when the SOCKS5 proxy is configured (the engine's creation for `proxy` with `proxyCredentials` or URL user info, `ResolvedProxy.socks5` for a resolver's)

**Open items.** See the roadmap ([docs/roadmap.md](../../roadmap.md)).
