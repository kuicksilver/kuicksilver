## <a id="s5-server-request-head-size"></a>§5 — server request-head size

Status: ✅ since 0.2.1 · [summary](../rfc-compliance.md#http)

Original row: RFC 6585 §5 (server request-head size).

**Requirement.** A request head (request line, header section, line ends and any empty lines before it) above 64 KiB, the HTTP/3 server's default `maxFieldSectionSize`, gets `431 Request Header Fields Too Large` with `Connection: close`, and what follows is read and dropped for up to 2 s so the client sees the answer.

**Recorded status.** ✅ 0.2.1

**How it is met.**

- a request line above 8 KiB (Ktor's parser limit) is a request-target longer than the server parses and gets `414 URI Too Long` with `Connection: close` (RFC 9112 §3 MUST; 0.2.1, before 400), or, when its method alone is that long, a method longer than any the server implements: `501 Not Implemented` (§3 SHOULD; 0.2.1), a field line above 8 KiB gets 400
- bodies do not count against the next head (before 0.2.1 there was no total limit)

**Tests that pin it.**

- `h1.H1PipelineHeadLimitTest.*` (including `negative_longRequestTargetGets414`, `negative_longMethodGets501`, `negative_longFieldLineGets400`), `ServerH1HeadLimitTest.negative_headerSectionSizeIsBounded`
