## <a id="tls-1-2-tcp-explicit-only"></a>(obsoleted by RFC 9846; TLS 1.2 itself stays as written there) — TLS 1.2 (TCP, explicit only)

Status: ✅ since 0.2.1 · [summary](../rfc-compliance.md#tls)

Original row: RFC 5246 (obsoleted by RFC 9846; TLS 1.2 itself stays as written there).

**Requirement.** TLS 1.2 (TCP, explicit only).

**Recorded status.** ✅ 0.2.0

**How it is met.**

- key exchange per RFC 10015 (ECDHE only)
- only with an explicit `TlsVersions`, only with EMS (RFC 7627 §5.2: an endpoint that does not interoperate with legacy peers SHOULD abort the handshake, and ksl's refusal is that local policy; the extension is named `extended_main_secret` by RFC 9846 App. D, which leaves RFC 7627's rules in place; RFC 9325 §3.5: TLS 1.2 implementations MUST support it)
- RFC 9325 §4.4 (SHOULD, RECOMMENDED limit 2^24.5 records for AES-GCM): with no KeyUpdate and no renegotiation a connection ends before its keys reach the AEAD's limit (2^24.5 records for AES-GCM, none for ChaCha20-Poly1305), with internal_error where an alert can be sent (a client) — C `tcp_record_limits_per_cipher`

**Tests that pin it.**

- rejected for QUIC when the configuration is built (`TlsConfigTest.quicRequiresTls13Only`)
- C `tcp_tls12_profile_and_ems` (`negative_tls12WithoutEmsRejected`: a TLS 1.2 peer without EMS is refused with `KSL_E_EMS_REQUIRED` and `handshake_failure` from either side), `TlsConnectionTest.tls12And13PeersNegotiateTls13`

**History.**

- 0.2.1: a peer without EMS is refused before Finished with `handshake_failure` (§7.2.2; the server when the ClientHello lacks it, the client when the ServerHello does), where it used to be dropped after the handshake without an alert
