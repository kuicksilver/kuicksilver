## <a id="datagram-frames"></a>DATAGRAM frames

Status: ✅ since 0.2.0 · [summary](../rfc-compliance.md#quic)

Original row: RFC 9221.

**Requirement.** DATAGRAM frames.

**Recorded status.** ✅ 0.2.0 (core)

**How it is met.**

- `max_datagram_frame_size` 65 535 by default (`QuicConfig.maxDatagramFrameSize`, 0 — do not advertise and reject the frames with PROTOCOL_VIOLATION)
- `ConnectionCore.maxDatagramPayload` = min(peer limit, MTU − short header − tag) − frame header (0 — the peer does not support it)
- sending through `DatagramSender.onTransmit(DatagramPacketWriter)` while a 1-RTT packet is assembled, only with an open congestion window, the frames are ack-eliciting, counted by CC, never retransmitted — `onAcked(id)`/`onLost(id)` (§5)
- receiving: a frame larger than our limit (the whole frame: type, the Length field only for 0x31, data — `DatagramCoreTest.typeWithoutLengthAtExactMax`, core review) → PROTOCOL_VIOLATION (§3), in Initial/Handshake → PROTOCOL_VIOLATION (decoder), a receive queue of 128 evicting the oldest and `ConnectionStats.datagramsDropped`, event `DatagramsReadable`, `readDatagram(into, offset)`
- coroutine API: `QuicConnection.sendDatagram(data, policy)` / `trySendDatagram` (without entering the loop: a bounded command queue — no more than `datagramSendQueue`, overflow evicts the oldest — + atomic counters; total buffered ≤ 2 × `datagramSendQueue` + 1), policies `DropOldest`, `Reject` (`QueueFull`, `sendDatagram` waits for room), `LatestWins(key)` (replacement in the queue by key), send queue ≤ 32 / 1 MiB (`datagramSendQueue`, `datagramSendQueueBytes`), `TooLarge(max)`/`DatagramTooLarge`, `Unsupported(PeerDoesNotSupport|Disabled)`/`DatagramUnsupported`, `datagrams: Flow<Datagram>` reads the core's queue directly (one buffer of 128 evicting the oldest), `maxDatagramSize: StateFlow<Int>`

**Tests that pin it.**

- `core.DatagramCoreTest.*` (10: `maxDatagramFrameSizeAdvertised`, `payloadLimitFromMtuAndPeer`, `peerWithoutSupportGivesZero`, `onTransmitCalledAtPacketAssembly`, `ackedCallback`, `datagramNeverRetransmitted`, `datagramsRespectCongestionWindow`, `negative_datagramInHandshakeLevel`, `datagramAboveAdvertisedSizeIsProtocolViolation`, `receiveQueueDropsOldestAt128`), `ReceivePathTest.datagramFrameWithoutSupportIsProtocolViolation`
- `api.DatagramApiTest.*` (9: `echoDatagrams`, `negative_datagramQueueCap`, `dropOldestFloodStaysBounded`, `latestWinsReplacesByKey`, `tooLargeResultAndException`, `unsupportedWhenPeerDisabled`, `unsupportedWhenLocallyDisabled`, `maxDatagramSizeFlowTracksPathMtu`, `sendDatagramUnderRejectSuspendsUntilSpace`), `core.DatagramCoreTest.typeWithoutLengthAtExactMax`, `DatagramApiAllocationTest.trySendNeverSuspendsOrAllocatesPerCall`, `testing.SimulatorTest.realtimeScenarioStreamsAndDatagrams`
- a frame always fits the room left in its packet (§5: no fragmentation): the payload offered is the largest whose type, Length and payload fit, for every room (RFC review: with 66 bytes left it was 64, a 67-byte frame, and the connection failed with an internal error) — `core.DatagramWriterTest.payloadOfRemainingAlwaysFits`
