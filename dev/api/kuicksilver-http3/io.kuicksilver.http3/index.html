Http3Connection
Link copied to clipboard
class Http3Connection : AutoCloseable

An HTTP/3 connection over a QuicConnection whose ALPN is h3 (RFC 9114). Create one with client or server: both open the control and QPACK streams and send SETTINGS at once, without waiting for the peer's (RFC 9114 section 6.2.1). The peer's transport parameters must allow those three unidirectional streams (section 6.2); when they cannot be opened within three seconds the connection closes with H3_GENERAL_PROTOCOL_ERROR.

Http3EarlyDataPolicy
Link copied to clipboard
sealed class Http3EarlyDataPolicy

What an HTTP/3 server does with a request that arrived in 0-RTT before the handshake completed (RFC 8470, ADR-0015). Early data can be replayed by an attacker (RFC 9846 section 8): only requests replayable says are safe to execute twice run at once. Every other one waits for the handshake (WaitForHandshake, the default; a replayed connection never completes it, so the request never runs) or is answered with 425 Too Early (Reject425), which a client repeats after its handshake (RFC 8470 section 5.2).

Http3Endpoint
Link copied to clipboard
class Http3Endpoint : AutoCloseable

HTTP/3 over a bound QUIC endpoint: the transport surface the Ktor engines use (layer rule, ADR-0005). TLS configurations must offer ALPN h3 (RFC 9114 section 3.1); an accepted connection that negotiated anything else is closed, and connect/connectEarly fail with H3_GENERAL_PROTOCOL_ERROR (Http3Exception.Protocol) when the server chose another protocol the client offered. SETTINGS_H3_DATAGRAM follows the transport: it is 1 only when QuicConfig.maxDatagramFrameSize is not 0. QuicConfig.maxUniStreams must be at least 3, so the peer can open its control and QPACK streams (RFC 9114 section 6.2): bind, connect and connectEarly throw IllegalArgumentException for a smaller value. With Http3Settings.webTransport is turned on (WebTransport needs reset_stream_at on both sides, draft-ietf-webtrans-http3-16 section 3.1), as the Ktor engines do.

Http3Request
Link copied to clipboard
class Http3Request

A client request (RFC 9114 section 4.1), built with http3Request (or Builder). authority and path become the pseudo-headers; headers must not contain pseudo-headers or connection-specific fields. request refuses with IllegalArgumentException what the peer would treat as malformed (RFC 9114 sections 4.2, 4.3.1): a method that is not a token, a path that does not start with / (or is * for OPTIONS), userinfo (user@) in authority, a host field differing from authority, te other than trailers, invalid field names or values, a protocol that is not a token (RFC 8441 section 4), trailers on a CONNECT (RFC 9114 section 4.4: only DATA follows its 2xx), and a CONNECT that enables the Capsule Protocol (Capsule-Protocol: ?1) with content-length, content-type or transfer-encoding (RFC 9297 section 3.2). A null body sends HEADERS with FIN; otherwise the channel is copied into DATA frames until it closes, then trailers (if any) are sent.

UdpProxy

class UdpProxy(val config: UdpProxyConfig = UdpProxyConfig())

A UDP proxy (RFC 9298) on an HTTP/3 server: serve answers one CONNECT-UDP request and relays its tunnel until it ends. The server's Http3Settings need enableConnectProtocol (RFC 9220), and h3Datagram for datagrams as QUIC DATAGRAM frames (without them the tunnel falls back to DATAGRAM capsules on the stream). Authenticate clients before calling serve: "HTTP servers that support UDP proxying ought to restrict its use to authenticated users" (section 7).

UdpTargetFilter
Link copied to clipboard
fun interface UdpTargetFilter

Which targets a UdpProxy sends to (RFC 9298 section 7). It sees each address the target resolved to (4 or 16 bytes), the host the client named (a literal or a DNS name) and the port; the proxy uses the first address it allows and answers 403 with proxy-status: ...; error=destination_ip_prohibited when it allows none. The check runs on resolved addresses, and the proxy sends to the very address it allowed, so a DNS answer cannot steer it elsewhere afterwards.

UdpTunnel
Link copied to clipboard
interface UdpTunnel

A UDP tunnel through a proxy (RFC 9298), from Http3Connection.connectUdp: UDP payloads to and from one target, carried as HTTP datagrams with Context ID 0 (section 5), as QUIC DATAGRAM frames when both sides negotiated HTTP/3 datagrams and as DATAGRAM capsules otherwise (RFC 9297 section 3.5). Like UDP, delivery is not guaranteed: datagrams that do not fit the connection to the proxy are refused (TooLarge), and the proxy may drop what its own link cannot carry.

interface WebTransportSession

A WebTransport session over HTTP/3 (draft-ietf-webtrans-http3-16): an Extended CONNECT stream that groups WebTransport streams and datagrams. With WebTransport flow control (section 5, on when both sides declare it in their SETTINGS) its streams and stream data stay within the peer's limits and a violation by the peer closes the session (WebTransportException.FlowControl); without it a connection carries one session (section 5.1).

acceptWebTransport
Link copied to clipboard
suspend fun Http3ServerRequest.acceptWebTransport(headers: Http3Headers = Http3Headers.Empty, protocol: String? = null): WebTransportSession

Server: accepts a WebTransport session (Http3ServerRequest.isWebTransport must be true, IllegalStateException otherwise). Waits up to ten seconds for the client's SETTINGS (section 7.1); without them, or without SETTINGS_H3_DATAGRAM=1, the request is malformed (section 3.1): it is answered with 400 and Http3Exception.Settings is thrown. A request with content-length, content-type or transfer-encoding cannot carry the session's capsules (RFC 9297 section 3.2): it is answered with 400 and Http3Exception.MessageError is thrown. Then answers 200 with headers, WT-Protocol when protocol is set (it must be one of Http3ServerRequest.availableProtocols, IllegalArgumentException otherwise) and, for a draft-02 client, the sec-webtransport-http3-draft: draft02 field it requires. Streams the client opened for the session before this are delivered to it. To refuse a session, answer with Http3ServerRequest.respond instead (a 4xx).

connectUdp

suspend fun Http3Connection.connectUdp(template: UdpProxyTemplate, targetHost: String, targetPort: Int, headers: Http3Headers = Http3Headers.Empty, closeTimeout: Duration = 5.seconds): UdpTunnel

Client: opens a UDP tunnel through the proxy at the other end of this connection (RFC 9298 section 3.4): an Extended CONNECT with :protocol connect-udp, the :scheme, :authority and :path of template expanded for targetHost and targetPort, capsule-protocol: ?1 and headers (a proxy-authorization, for example). The template is checked before anything is sent (section 2), and so is the target (section 3): IllegalArgumentException otherwise. Any answer other than a 2xx fails the call with Http3Exception.ConnectRejected, whose headers carry the proxy's proxy-status (section 3.5: "Any response other than a successful response indicates that the request has failed"); a server without Extended CONNECT fails it with Http3Exception.Settings. Datagrams may be sent once this returns.

webTransport
Link copied to clipboard
suspend fun Http3Connection.webTransport(request: Http3Request, protocols: List<String> = emptyList()): WebTransportSession

Client: opens a WebTransport session with an Extended CONNECT to request's authority and path (its method is replaced by CONNECT). Needs Http3Settings.webTransport on this connection (IllegalStateException otherwise) and waits up to ten seconds for the server's SETTINGS, which must offer WebTransport, Extended CONNECT and HTTP datagrams (Http3Exception.Settings otherwise), then up to ten seconds for the answer to the CONNECT (WebTransportException.Timeout otherwise; the CONNECT is reset with H3_REQUEST_CANCELLED). The draft the server speaks picks the :protocol token: webtransport-h3 for draft-15 and later, else webtransport with sec-webtransport-http3-draft02: 1. protocols are offered in WT-Available-Protocols (printable ASCII each); a WT-Protocol answer that names another protocol closes the session with WT_ALPN_ERROR and throws WebTransportException.Alpn, one that is no valid Structured Field String is ignored (WebTransportSession.protocol is null). A non-2xx answer throws Http3Exception.ConnectRejected (redirects are not followed, section 3.2). Several sessions share the connection when both sides declared WebTransport flow control (section 5.1), up to Http3Settings.webTransportMaxSessions; one more, or a second without flow control, throws WebTransportException.ConnectionFull before anything is sent, and a server that refuses one more (its limit, section 5.2) answers with H3_REQUEST_REJECTED, Http3Exception.RequestNotProcessed.
