Http3Connection

class Http3Connection : AutoCloseable(source)

An HTTP/3 connection over a QuicConnection whose ALPN is h3 (RFC 9114). Create one with client or server: both open the control and QPACK streams and send SETTINGS at once, without waiting for the peer's (RFC 9114 section 6.2.1). The peer's transport parameters must allow those three unidirectional streams (section 6.2); when they cannot be opened within three seconds the connection closes with H3_GENERAL_PROTOCOL_ERROR.

acceptRequest

suspend fun acceptRequest(): Http3ServerRequest

Server: the next request; malformed requests are answered at the stream level and never returned. A caller cancelled while it waits takes no request with it: the next call returns it. A wrapper that is itself cancelled after this returned (withTimeout, async, withContext) may still drop the request it got, so accept in one long-lived loop rather than polling with a timeout. Each request returned holds one of the client's streams (its MAX_STREAMS credit) until the application is done with it; see Http3ServerRequest for when that is. A request kept without that holds its stream until the connection ends.

connect
Link copied to clipboard
suspend fun connect(request: Http3Request, protocol: String): Http3Stream

Client: Extended CONNECT (RFC 9220) with :protocol = protocol (websocket, ...; a token, RFC 8441 section 4). Waits for the peer's SETTINGS and needs SETTINGS_ENABLE_CONNECT_PROTOCOL (Http3Exception.Settings otherwise); a non-2xx answer throws Http3Exception.ConnectRejected, and a 2xx that enables the Capsule Protocol against RFC 9297 section 3.2 (with content-length, content-type or transfer-encoding, or a 204, 205 or 206) is malformed: the stream is aborted with H3_MESSAGE_ERROR and Http3Exception.MessageError is thrown. The method of request is replaced by CONNECT.

connectUdp
Link copied to clipboard
suspend fun Http3Connection.connectUdp(template: UdpProxyTemplate, targetHost: String, targetPort: Int, headers: Http3Headers = Http3Headers.Empty, closeTimeout: Duration = 5.seconds): UdpTunnel

Client: opens a UDP tunnel through the proxy at the other end of this connection (RFC 9298 section 3.4): an Extended CONNECT with :protocol connect-udp, the :scheme, :authority and :path of template expanded for targetHost and targetPort, capsule-protocol: ?1 and headers (a proxy-authorization, for example). The template is checked before anything is sent (section 2), and so is the target (section 3): IllegalArgumentException otherwise. Any answer other than a 2xx fails the call with Http3Exception.ConnectRejected, whose headers carry the proxy's proxy-status (section 3.5: "Any response other than a successful response indicates that the request has failed"); a server without Extended CONNECT fails it with Http3Exception.Settings. Datagrams may be sent once this returns.

goAway
Link copied to clipboard
suspend fun goAway()

Graceful shutdown with GOAWAY (RFC 9114 section 5.2). A server announces 2^62-4, waits about two round trips, then announces the first request id it will not process (those are reset with H3_REQUEST_REJECTED, which clients may retry elsewhere); once its accepted requests are answered and acknowledged, the client closes the connection with H3_NO_ERROR (a Kuicksilver client does once it read its responses), or the server does three seconds later. A client sends GOAWAY(0) and stops issuing requests (a request after it fails with Http3Exception.RequestNotProcessed, retry-safe, as one above a received GOAWAY); a client that receives GOAWAY closes with H3_NO_ERROR once it is idle.

request
Link copied to clipboard
suspend fun request(request: Http3Request): Http3Response

Client: sends request and returns at its final response; interim (1xx) responses go to onInformational. Fails with Http3Exception.RequestNotProcessed after GOAWAY, with Http3Exception stream errors for this request (the connection lives on), and with the connection's error once it is gone. Cancelling the call resets the stream with H3_REQUEST_CANCELLED. A request the peer would have to treat as malformed (RFC 9114 sections 4.2, 4.3.1: see Http3Request) throws IllegalArgumentException before a stream is opened; so do its trailers, which also abandon the request (the stream is reset with H3_REQUEST_CANCELLED). A request with a protocol (Extended CONNECT) waits for the peer's SETTINGS and throws IllegalArgumentException unless they enable it (RFC 9220 section 3); connect is the usual way to make one. A request that fails, also with IllegalStateException on a server's connection, ends its Http3Request.body with the exception it throws, so a coroutine writing the body is released, its next write failing with that exception; except one that fails with Http3Exception.RequestNotProcessed whose neverSent is true: that body was never read and can be sent again.

webTransport
Link copied to clipboard
suspend fun Http3Connection.webTransport(request: Http3Request, protocols: List<String> = emptyList()): WebTransportSession

Client: opens a WebTransport session with an Extended CONNECT to request's authority and path (its method is replaced by CONNECT). Needs Http3Settings.webTransport on this connection (IllegalStateException otherwise) and waits up to ten seconds for the server's SETTINGS, which must offer WebTransport, Extended CONNECT and HTTP datagrams (Http3Exception.Settings otherwise), then up to ten seconds for the answer to the CONNECT (WebTransportException.Timeout otherwise; the CONNECT is reset with H3_REQUEST_CANCELLED). The draft the server speaks picks the :protocol token: webtransport-h3 for draft-15 and later, else webtransport with sec-webtransport-http3-draft02: 1. protocols are offered in WT-Available-Protocols (printable ASCII each); a WT-Protocol answer that names another protocol closes the session with WT_ALPN_ERROR and throws WebTransportException.Alpn, one that is no valid Structured Field String is ignored (WebTransportSession.protocol is null). A non-2xx answer throws Http3Exception.ConnectRejected (redirects are not followed, section 3.2). Several sessions share the connection when both sides declared WebTransport flow control (section 5.1), up to Http3Settings.webTransportMaxSessions; one more, or a second without flow control, throws WebTransportException.ConnectionFull before anything is sent, and a server that refuses one more (its limit, section 5.2) answers with H3_REQUEST_REJECTED, Http3Exception.RequestNotProcessed.
