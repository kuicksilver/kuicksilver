kuicksilver-http3/io.kuicksilver.http3/UdpProxy/serve

serve

suspend fun serve(request: Http3ServerRequest)(source)

Serves request, an Extended CONNECT for connect-udp (ConnectUdp.isConnectUdp), and returns when its tunnel ended. In order (RFC 9298 sections 3.1, 3.4, 7):

  • not a CONNECT-UDP request: 400 (http_request_error); a path that does not fit UdpProxyConfig.pathTemplate: 404; a target_host or target_port that breaks section 3, or no capsule-protocol: ?1 while UdpProxyConfig.requireCapsuleProtocolField: 400;

  • UdpProxyConfig.maxTunnels reached: 503, UdpProxyConfig.maxTunnelsPerClient: 429 (connection_limit_reached);

  • a DNS name is resolved before the answer ("the UDP proxy MUST perform DNS resolution before replying"): a failure or no address is 502 with proxy-status: <name>; error=dns_error, a timeout 504 with dns_timeout;

  • no address the UdpProxyConfig.targetFilter allows: 403 with destination_ip_prohibited;

  • the socket cannot be opened: 502 with proxy_internal_error;

  • otherwise 200 with capsule-protocol: ?1: the socket is open (a successful response "indicates that the UDP proxy has opened a socket to the requested target"), and nothing is sent to the target before it.

Then HTTP datagrams with Context ID 0 become UDP payloads to the target and the target's payloads become HTTP datagrams; datagrams with other Context IDs are dropped, and one whose payload exceeds 65527 bytes aborts the stream with H3_DATAGRAM_ERROR (section 5). Only datagrams from the target's address and port are taken (section 3.1). The tunnel ends, and the socket closes with it, when the client ends the stream (FIN: our side is closed too), when it resets it or its connection is gone, when the socket fails (the stream is reset and stopped with H3_CONNECT_ERROR: "If a UDP proxy is notified by its operating system that its socket is no longer usable, it MUST close the request stream"), or after UdpProxyConfig.idleTimeout without traffic (FIN and STOP_SENDING H3_NO_ERROR). Cancelling the call ends the tunnel the same way, with H3_CONNECT_ERROR.
