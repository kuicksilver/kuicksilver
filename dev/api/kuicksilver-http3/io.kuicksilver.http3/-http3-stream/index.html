Http3Stream

interface Http3Stream(source)

The bidirectional data stream of an Extended CONNECT (RFC 9220), with the HTTP datagrams bound to it (RFC 9297). Bytes written to output travel in DATA frames; closing it sends FIN. WebSocket frames (RFC 6455) or capsules go inside.

datagrams
Link copied to clipboard
abstract val datagrams: Flow<ByteArray>

HTTP datagrams received for this stream (newest 32 kept when nobody collects). The flow ends once input's side of the stream closed (the peer's FIN or reset, or our STOP_SENDING): datagrams arriving after that are dropped (RFC 9297 section 2.1); those received before are still delivered. A stream whose protocol has no datagram semantics (websocket, RFC 9220; a classic CONNECT) gets none: a datagram for it aborts it with H3_DATAGRAM_ERROR (RFC 9297 section 2).

Sends an HTTP datagram on this stream; Unsupported until both sides sent SETTINGS_H3_DATAGRAM=1 (RFC 9297 section 2.1.1), Closed once our send side is closed — output closed (FIN) or failed, or reset — since datagrams must not be sent then (RFC 9297 section 2.1); TooLarge with max 0 when the peer's max_datagram_frame_size leaves no room for the Quarter Stream ID, so not even an empty HTTP datagram fits; and always Closed on a stream whose protocol has no datagram semantics (websocket, a classic CONNECT; RFC 9297 section 2: "HTTP Datagrams MUST only be sent with an association to an HTTP request that explicitly supports them").

useCapsuleProtocol
Link copied to clipboard
open fun useCapsuleProtocol(config: CapsuleConfig = CapsuleConfig()): CapsuleStream

Speaks the Capsule Protocol (RFC 9297 section 3) on this stream from now on: input, output and datagrams then belong to the returned CapsuleStream and must not be used directly. Call it at most once per stream, before reading input or writing output. Only an Extended CONNECT whose protocol has datagram semantics speaks it: the Capsule Protocol "only applies to definitions of new HTTP upgrade tokens" (section 3.2), which a classic CONNECT has not and websocket (RFC 9220) does not use, so on those streams IllegalStateException is thrown and the stream is left as it was.
