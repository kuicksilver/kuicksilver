UdpTunnel

interface UdpTunnel(source)

A UDP tunnel through a proxy (RFC 9298), from Http3Connection.connectUdp: UDP payloads to and from one target, carried as HTTP datagrams with Context ID 0 (section 5), as QUIC DATAGRAM frames when both sides negotiated HTTP/3 datagrams and as DATAGRAM capsules otherwise (RFC 9297 section 3.5). Like UDP, delivery is not guaranteed: datagrams that do not fit the connection to the proxy are refused (TooLarge), and the proxy may drop what its own link cannot carry.

The tunnel lives as long as its request stream: close ends it; the proxy ends it when its socket fails or after a period without traffic (two minutes at least, section 3.1), and payloads then completes.

asDatagramIo
Link copied to clipboard
abstract fun asDatagramIo(): DatagramIo

The tunnel as a UDP socket for a QUIC endpoint (quicEndpointConfig { io = { tunnel.asDatagramIo() } }), so that a QUIC or HTTP/3 connection to remoteAddress runs through the proxy (proxied QUIC). Every datagram the endpoint sends goes to the target whatever its address (a tunnel has one target, so a server's preferred address and other paths are unreachable through it); every one received is reported as coming from remoteAddress. The socket has no ECN, GSO or Don't Fragment (io.kuicksilver.quic.IoCapabilities.Portable), so the QUIC connection inside keeps 1200-byte datagrams; the connection to the proxy must carry HTTP datagrams of 1200 bytes plus a few bytes of framing, which needs its path MTU above about 1250 (a socket that sets Don't Fragment, so DPLPMTUD can find it): until then the datagrams are refused as too large and the inner handshake waits. A datagram the tunnel refuses counts as lost on the path. Closing the socket closes the tunnel; once the tunnel ended, receive throws. Call it once.
