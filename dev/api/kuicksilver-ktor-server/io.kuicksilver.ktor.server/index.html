class KuicksilverPlainConnector : EngineConnectorConfig

A plain HTTP/1.1 connector, as Ktor's connector { }, with trustedGateway and, opt-in, cleartext HTTP/2 (h2c): made by plainConnector { ... } in the engine configuration. KuicksilverServerEventListener
Link copied to clipboard
abstract class KuicksilverServerEventListener

Hears the server engine's connections and requests over HTTP/1.1, HTTP/2 and HTTP/3 (docs/guide/ktor.md, "Observability"); set it with eventListener in the engine configuration. Every method has an empty default. A connection reports connectionOpened once its TLS handshake (HTTP/1.1, HTTP/2) or QUIC handshake (HTTP/3) completed, and connectionClosed when the engine is done with it; each request reports requestStarted before the application's pipeline and requestEnded after it.

class ProxyHeader

The PROXY protocol header a connection began with (ProxyProtocolConfig). ProxyHeader.sourceAddress and ProxyHeader.destinationAddress are the client's address and the one it connected to on the proxy: IP literals (a dotted quad, or IPv6 as RFC 5952 recommends) for ProxyFamily.Inet and ProxyFamily.Inet6, the socket path for ProxyFamily.Unix (an abstract one as @ and its name), null for a ProxyCommand.Local header and for ProxyFamily.Unspecified. class ProxyProtocolConfig

The PROXY protocol (HAProxy, "The PROXY protocol", versions 1 and 2) on one TCP connector, plain or TLS: a proxy or L4 load balancer in front of the server sends a header with the client's address before anything else on the connection, and the engine reports that address as the request's origin (call.request.origin), while call.request.local keeps the TCP peer (the proxy). neverIndexedHeaders

val ApplicationRequest.neverIndexedHeaders: List<Pair<String, String>>

The request fields the client sent as literals never indexed, over HTTP/2 (RFC 7541 section 6.2.3) or with QPACK's 'N' bit over HTTP/3 (RFC 9204 section 4.5.4), with lowercase names, in the order received; empty over HTTP/1.1 and other engines. A proxy that forwards one of them MUST keep that representation (RFC 7541 section 7.1.3, RFC 9204 section 7.1.3): pass its name to the Kuicksilver client's neverIndex on the request it sends on.

priority
Link copied to clipboard
val ApplicationRequest.priority: StreamPriority

The client's current priority signal for this request (RFC 9218): over HTTP/3 and HTTP/2 the priority field and the PRIORITY_UPDATE frames that followed it, over HTTP/1.1 the Priority field; urgency 3, not incremental, when the client sent none or another engine serves the call. A malformed or out-of-range parameter reads as its default (section 4). Over HTTP/3 and HTTP/2 the engine schedules the response by this signal (section 10); over HTTP/1.1 it is advisory, since one connection carries one response at a time.

receivedEarly
Link copied to clipboard
val ApplicationRequest.receivedEarly: Boolean

True when this request may be a replay of early data (RFC 9846 section 8): an HTTP/3 request that arrived in 0-RTT and runs before the handshake completed (quicEarlyData, ADR-0015), or a request over HTTP/1.1 or HTTP/3 that a gateway marked with Early-Data because it received it in early data on a previous hop (RFC 8470 section 5.1). Only requests the http3Settings.earlyData policy declares replayable (GET, HEAD and OPTIONS by default; over HTTP/1.1 these methods) get here so marked: any other request with Early-Data is answered with 425 Too Early without reaching the application, since waiting for this hop's handshake cannot make it safe. The engine never adds Early-Data itself.

The application code a session ends with when its webTransport handler throws; the reason is empty, so nothing of the exception reaches the client. connectUdp
Link copied to clipboard
fun Route.connectUdp(proxy: UdpProxy = UdpProxy()): Route

Serves CONNECT-UDP (RFC 9298) with proxy on an engine with connectUdp = true: an Extended CONNECT over HTTP/3 whose :protocol is connect-udp, at any path (the proxy matches its own pathTemplate and answers 404 for another). Nothing else matches the route: HTTP/1.1 and HTTP/2 requests and other CONNECTs go on to the routes that follow; a CONNECT-UDP request no route takes gets Ktor's 404, and one another route answers with a 2xx gets 501 (no tunnel was opened). Put it inside an authenticate { } block or behind your own check: "HTTP servers that support UDP proxying ought to restrict its use to authenticated users" (RFC 9298 section 7); a refusal there (401, 407) goes out as it is. The proxy answers and relays the tunnel (UdpProxy.serve); the call ends with the tunnel.

neverIndex
Link copied to clipboard
fun ApplicationResponse.neverIndex(vararg names: String)

Sends this response's fields named names (any case) as literals never indexed: over HTTP/2 (RFC 7541 section 6.2.3) and over HTTP/3 with QPACK's 'N' bit (RFC 9204 section 4.5.4). The encoder neither adds them to the dynamic table nor refers to an entry for them, and an intermediary has to keep that representation (RFC 7541 section 7.1.3, RFC 9204 section 7.1.3). For secrets that are short or easy to guess, and for a proxy that forwards a field it received never indexed (neverIndexedHeaders of the request, or of the response it relays). The engine already sends set-cookie so. Each call adds to the names; call it before the response starts. Over HTTP/1.1 it changes nothing.

fun ApplicationResponse.priority(urgency: Int? = null, incremental: Boolean? = null)

Sets the response's Priority field (RFC 9218 section 5) with only the given parameters: one left null keeps the client's value (section 8, "disinterest to change"). Over HTTP/3 and HTTP/2 the engine also schedules the response by the client's signal merged with these parameters, and later PRIORITY_UPDATEs from the client no longer change it; over HTTP/1.1 only the field is sent. Call it before the response starts.
