webTransport

fun Route.webTransport(path: String, protocols: List<String> = emptyList(), checkOrigin: (origin: String?, call: ApplicationCall) -> Boolean = ::sameHostOrigin, handler: suspend (WebTransportSession) -> Unit): Route(source)

Serves WebTransport sessions (draft-ietf-webtrans-http3-16) on path: an Extended CONNECT whose :protocol is webtransport-h3 or webtransport, over HTTP/3, on an engine with webTransport = true. Nothing else matches the route: HTTP/1.1 requests and other CONNECTs go on to the routes that follow, and a WebTransport request without a matching route gets Ktor's 404 (one that another route answers with a 2xx gets 501: no session was accepted).

checkOrigin sees the request's origin field (null when absent) and refuses the session with 403 when it returns false; the default, sameHostOrigin, admits the server's own origin and clients that send none (browsers always do). The server picks the first of protocols (its preference order) the client offers, if any. Then the session is accepted (200) and handler runs; when it returns the session is closed with code 0, when it throws with WEB_TRANSPORT_HANDLER_FAILED and an empty reason, and the exception goes on to Ktor as a failed call does.
