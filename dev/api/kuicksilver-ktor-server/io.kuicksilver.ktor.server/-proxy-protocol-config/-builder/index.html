headerTimeout
Link copied to clipboard
var headerTimeout: Duration

How long a connection may take, from accept, to deliver its whole header: 5 s by default, at least 3 s (section 2: "The receiver may apply a short timeout and decide to abort the connection if the protocol header is not seen within a few seconds (at least 3 seconds to cover a TCP retransmit)."). The wait is also cut to what is left of the engine's requestHeaderTimeoutSeconds, which goes on counting from accept through the TLS handshake and the first request head; the engine does not start a PROXY connector with requestHeaderTimeoutSeconds below 3. A proxy sends the header at once ("The sender must always ensure that the header is sent at once"), so a short bound cuts a peer that trickles it without hurting a proxy. Throws at build below 3 s.

maxHeaderSize
Link copied to clipboard
var maxHeaderSize: Int

The longest header accepted, in bytes: 4096 by default, from 232 (a version 2 header with AF_UNIX addresses and no TLV) to 65551 (the 16 fixed bytes and the largest length field). A version 1 header is never longer than 107 bytes whatever this says; a version 2 header whose length field says more than this is refused before its body is read.

trustedSources
Link copied to clipboard
val trustedSources: MutableList<String>

The TCP peers allowed to send the header: IPv4 or IPv6 addresses, each alone or as a CIDR block (10.0.0.0/8, 2001:db8::/32). At least one is required; a block with bits set past its prefix (10.0.0.1/8), a zone ID or anything else that is not a numeric address is refused at build. An IPv4-mapped block (::ffff:10.0.0.0/104) is the IPv4 block it maps; IPv4 peers match IPv4 blocks only, also where the listener reports them as IPv4-mapped IPv6 addresses.
