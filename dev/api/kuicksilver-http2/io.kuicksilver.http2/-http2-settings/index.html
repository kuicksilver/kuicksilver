Http2Settings

class Http2Settings(val headerTableSize: Int, val maxConcurrentStreams: Int = 100, val initialStreamWindow: Int, val maxStreamWindow: Int, val initialConnectionWindow: Int, val maxConnectionWindow: Int, val maxFrameSize: Int, val maxHeaderListSize: Int, val settingsAckTimeout: Duration = 10.seconds, val maxContinuationFrames: Int = 8, val maxControlFramesQueued: Int, val maxEmptyFrames: Int = 100, val resetBurst: Int, val resetsPerSecond: Int = 33, val maxHeaderBlockTime: Duration = 10.seconds, val glitchBurst: Int, val glitchesPerSecond: Int = 330)(source)

The local side of an HTTP/2 connection: the SETTINGS we send (RFC 9113 section 6.5.2), our flow-control windows and the limits we hold the peer to (threat model 3.23). Every limit is per connection; the defaults follow the QUIC defaults of this project for the windows and the published fixes of other HTTP/2 stacks for the flood limits. The constructor throws IllegalArgumentException for a value out of range.

val glitchBurst: Int

The burst of the glitch budget; default 10 000 (the numbers are nghttp2's). Counted events: PRIORITY, unknown frame types, SETTINGS, empty DATA without END_STREAM, a PING with no DATA or HEADERS of ours since the previous PING (a bandwidth probe that follows our data is free, as grpc-go's ping strikes), and every stream error the peer causes.

val maxHeaderListSize: Int

SETTINGS_MAX_HEADER_LIST_SIZE: the largest field section we decode (name + value + 32 per field), 1..2^30 - 1; default 64 KiB. A field block above it fails only its stream; its compressed form (HEADERS plus CONTINUATION) is buffered up to twice this before decoding, and beyond that the connection ends.
