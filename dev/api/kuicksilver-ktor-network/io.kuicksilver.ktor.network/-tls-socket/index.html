attachForReading
Link copied to clipboard
open override fun attachForReading(channel: ByteChannel): WriterJob

The peer's plaintext goes to the application's channel. A session that failed (a reset, a TLS error) fails that channel, not ends it: ktor's copyTo ends its loop on a source closed with a failure as on one closed cleanly and returns normally, so a reset before the application opened its channel, or landing between two of its reads after the last bytes, reached the application as a clean end, and a body delimited by the connection's close passed cut for whole. The channel fails with the session's TlsException itself: ktor's channels wrap a failure in ClosedByteChannelException where they hand it on, and a second wrapping (ktor's copyTo closed the channel with the wrapped failure it caught) hid the TlsException two causes deep. A channel opened with openDeliveringReadChannel keeps the plaintext relayed before the failure readable (ReadDelivery).

attachForWriting
Link copied to clipboard
open override fun attachForWriting(channel: ByteChannel): ReaderJob

The application's plaintext goes through the TLS session to the raw socket. When the application's channel fails (a handler that threw mid-response), or the pump does, the connection never ends with close_notify: a close_notify and a FIN would end the stream as if complete, and a peer reading a body delimited by the connection's close would take the cut one for the whole. It ends with the fatal alert internal_error after what was sent, then a FIN, where OpenSSL can send one (RFC 9846 section 6.1; failTls), else with a reset (abortTls). A channel closed normally ends with close_notify on close.

close
Link copied to clipboard
open override fun close()

Graceful: pending plaintext is encrypted and flushed, close_notify is sent, then the raw socket closes; on a server the raw socket's write side ends right after close_notify (its FIN), and the client's close_notify or FIN is awaited only after that (at most 3 s), so a client that never answers does not hold the FIN back. Runs in the socket's scope. On a client (Socket.tls) bounded: when the raw socket has not closed after 3 s in all (a peer that stopped reading holds the flush, close_notify and the raw socket's last write), what is still queued is dropped, the TLS session is freed and the raw socket is aborted as by abort, which releases its descriptor. On a server (Socket.tlsServer) the close waits for the client to take the last response, however slowly it reads; whoever accepted the socket bounds it.

tls

suspend fun Socket.tls(config: TlsConfig, context: CoroutineContext = EmptyCoroutineContext): TlsSocket

Wraps a connected ktor-network Socket in TLS as a client (module kuicksilver-ktor-network, ADR-0005): the handshake completes before this returns; the result is a Socket whose channels carry plaintext. Unlike ktor's own Socket.tls, this works on every platform and offers TLS 1.3, ALPN and pins.
