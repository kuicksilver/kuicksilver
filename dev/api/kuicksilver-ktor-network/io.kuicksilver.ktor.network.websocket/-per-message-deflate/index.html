PerMessageDeflate

class PerMessageDeflate : WebSocketExtension<PerMessageDeflate.Config> (source)

The WebSocket per-message compression extension permessage-deflate (RFC 7692) for Ktor's WebSockets plugins, on every target: java.util.zip on the JVM and Android, the platform's zlib on Kotlin/Native (libz.so.1 on Linux, the system's on Apple, linked statically on Windows).

HttpClient(Kuicksilver) {
    install(WebSockets) { extensions { install(PerMessageDeflate) } }
}
// a server, on any engine
install(WebSockets) { extensions { install(PerMessageDeflate) { maxInflatedMessageSize = 1024 * 1024 } } }

It works with any Ktor engine. A compressed message that inflates to more than Config.maxInflatedMessageSize is refused: Kuicksilver's engines decompress the frames themselves as they arrive, in pieces of 64 KiB, and close the connection with 1009 (message too big, RFC 6455 section 7.4.1) when a message passes the limit; on another engine the extension decompresses the reassembled message in Ktor's session, in the same pieces, and fails it with FrameTooBigException (what goes on the wire then is the engine's and Ktor's session's choice). Malformed compressed data fails the connection with 1002 (protocol error) on Kuicksilver's engines, with ProtocolViolationException elsewhere.

Negotiation (RFC 7692 sections 5, 7 and 7.1). As a client it offers permessage-deflate with client_no_context_takeover and server_no_context_takeover as configured; it does not offer client_max_window_bits, so it compresses with a 32 KiB window. A response that is not a valid acceptance of that offer (an unknown, repeated or malformed parameter, client_max_window_bits, more than one permessage-deflate, or a requested server_no_context_takeover left out) fails the handshake with ProtocolViolationException; any server_max_window_bits from 8 to 15 is accepted (the inflater's 32 KiB window reads every smaller one). As a server it accepts the first offer it can honour and declines invalid ones (section 7): it echoes server_no_context_takeover and client_no_context_takeover (adding them when configured), answers server_max_window_bits with the offered value when its deflater can keep to it (9 to 15 on Kotlin/Native, 15 on the JVM, whose Deflater has a fixed window, and declines the offer otherwise), and takes client_max_window_bits as a hint it leaves unanswered.

Only Text and Binary messages are compressed (control frames never are, RFC 7692 section 6), with RSV1 on the first frame of a message only (section 6.1); a fragmented message is one DEFLATE stream across its frames. Compression and secrets: a message compressed in a window shared with attacker-chosen data can leak a secret through its size (CRIME, BREACH; section 8); keep such messages uncompressed with Config.compressIf, or use the *_no_context_takeover settings to stop one message from sharing a window with the next.

Memory per connection: the deflater (≈ 256 KiB of zlib state with a 32 KiB window) and the inflater (≈ 40 KiB), each made on first use, plus the 64 KiB piece the output is produced in. Kuicksilver's engines free the zlib state when the session ends; on other engines it is freed when the extension is garbage collected.

processOutgoingFrame
Link copied to clipboard
open override fun processOutgoingFrame(frame: Frame): Frame

Compresses a Text or Binary frame (RSV1 on the first frame of a message, RFC 7692 section 6.1); other frames are returned unchanged. Called by Ktor's session for each outgoing frame, in order. A text message it compresses must be UTF-8 as a whole (RFC 6455 section 5.6, MUST; once compressed, nothing after the extension can check it): at the first frame that shows it is not, the frame fails with ProtocolViolationException, which ends Ktor's session without sending it.
