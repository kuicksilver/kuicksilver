SocketDefunctException

class SocketDefunctException(message: String, val errno: Int = 0, cause: Throwable? = null) : IOException(source)

A DatagramIo can no longer carry datagrams: the system took the socket away or the network under it went down, so neither a retry nor waiting brings it back. iOS does this to the sockets of a suspended app (ENOTCONN, EBADF, EPIPE after the app returns to the foreground); ENETDOWN, ENETUNREACH and EHOSTUNREACH on receive mean the interface went away.

The endpoint loop does not fail the connection or the endpoint for it: it stops using the socket, reports PathEvent.SocketLost for every path on it, and the connection waits, within its idle timeout, for a move to a new socket (QuicConnection.rebind, QuicConnection.migrate or a NetworkMigrator). A server endpoint's own socket is the exception: it ends the endpoint, since its clients address that port.

A custom DatagramIo throws it from receive or send for the same conditions.
