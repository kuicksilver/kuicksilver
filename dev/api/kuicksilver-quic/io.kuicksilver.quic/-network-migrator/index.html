NetworkMigrator

class NetworkMigrator<N : Any>(connection: QuicConnection, networks: Flow<N?>, openIo: suspend (N) -> DatagramIo, scope: CoroutineScope) : AutoCloseable(source)

Keeps a client connection on the current network: whenever networks reports a different network, it opens a socket on it through openIo and migrates the connection there (RFC 9000 section 9), then closes the path it left.

  • The first non-null value is the network the connection is on already: nothing happens.

  • A different value opens openIo(network) and migrates (QuicConnection.addPath, QuicPath.probe, QuicPath.switchTo). On success the previous path is closed (its socket too, unless it is the endpoint's own) and MigrationEvent.Migrated follows. On failure (the new network never answers, openIo throws, the server sent disable_active_migration) the new path and its socket are closed, the connection stays where it was and MigrationEvent.Failed follows.

  • Right after the handshake the server may not have given the client a spare connection ID yet (its NEW_CONNECTION_ID frames are on their way): the probe waits for one (QuicPath.probe). If none comes in time, MigrationEvent.Failed reports a PathValidationException with PathFailureReason.NoSpareConnectionId, and the migrator tries the same network again as soon as an ID arrives (unless the network changed meanwhile).

  • null (no network) emits MigrationEvent.NetworkLost and waits: the next network is migrated to, unless it is the one the connection is still on. Like Chromium's QUIC session pool, the connection is not closed on a network loss; its idle timeout decides if no network comes back.

  • If networks throws, MigrationEvent.SourceFailed is the last event and the migrator stops; the exception never reaches scope. When networks completes, the migrator stops too.

  • PathEvent.SocketLost for the active path (iOS reclaimed the socket of a suspended app) opens a fresh socket on the current network and migrates to it, reported as MigrationEvent.Migrated with old == new; nothing happens while there is no network.

  • Repeated equal values are ignored. A change while a migration runs supersedes it: the unfinished path and its socket are closed and nothing is reported for it.

The migrator stops when close is called, when scope is cancelled or when the connection ends (a migration cut short by the end of the connection reports nothing: no MigrationEvent.Failed for a dead connection). Server connections are rejected with IllegalArgumentException: only the client migrates (RFC 9000 section 9).

Parameters

opens a socket on a network. It is not cancelled midway (a superseded or closed migration closes the socket it returns), so it should not wait long.

close
Link copied to clipboard
open override fun close()

Stops following the networks. A migration that has not switched yet is abandoned: its new path and socket are closed, nothing is reported, and the connection stays on the path it was on. A switch already under way completes (the connection is on the new network then) and still reports MigrationEvent.Migrated. The connection stays open. Thread-safe, also against a concurrent start.

Starts following networks in the scope; once only (IllegalStateException on a second call, also from another thread). The job ends with close; after close it ends at once. Thread-safe.
