key

The AES-128 key, made with QuicCrypto.newLoadBalancerKey(bytes) (which wipes bytes; the key material then lives in the native layer only), or null for plaintext connection IDs. The caller owns it; an endpoint takes its own copy when it is given this configuration (at build or QuicEndpoint.updateLoadBalancer), so the caller may close it after that. Draft section 9.6: "the server MUST NOT reuse a nonce until it switches to a configuration with new keys". Within a process no nonce of a key and nonce length (in clear: of a nonce length) is ever used twice, whatever the endpoints and server IDs that share them. Across processes that holds only with nonceReservation; without one, the operator must give every process start a key no earlier process used (a fresh key per process start and per instance). A plaintext configuration (no key) must have a nonceReservation: IllegalArgumentException otherwise.
