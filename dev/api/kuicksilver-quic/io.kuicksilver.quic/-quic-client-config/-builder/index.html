earlyData

var earlyData: EarlyDataState

Default EarlyDataState.Disabled. Otherwise the endpoint keeps the server's session tickets (per endpoint, single use) and QuicEndpoint.connectEarly sends what the application writes before the handshake completes in 0-RTT. 0-RTT data can be replayed by an attacker (RFC 9846 section 8): send early only what is safe to execute twice.

tokenStore
Link copied to clipboard
var tokenStore: QuicTokenStore?

Default null: no tokens are kept. Otherwise the endpoint stores the address-validation tokens the server sends in NEW_TOKEN frames (RFC 9000 section 8.1.3) under the server name and port, and takes one before each later connection to that server to send in its Initials: a server that asks unvalidated clients for a Retry then lets this one in without the extra round trip. Off by default because a token links the connections that present it to the one it came from, across networks (see QuicTokenStore on privacy). MemoryTokenStore keeps them in memory.
