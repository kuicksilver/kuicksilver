EndpointCore

class EndpointCore(source)

The sans-IO endpoint (ADR-0004): routes datagrams to connections by keyed connection ID, queues client Initials for ConnectionAdmission, creates server connections in processPending, and answers unknown versions, forged tokens and unknown short-header CIDs statelessly under a rate limit. One endpoint loop drives it; nothing here is thread-safe.

A new client Initial takes two steps: handleDatagram runs only the cheap checks (1200 bytes, version, DCID length, reflective source port) and copies the datagram into a bounded queue; the runtime then calls processPending once per receive batch, which checks the Retry token, the hard limits and the admission policy, and creates the connection.

processPending
Link copied to clipboard
fun processPending(now: TimeMark, max: Int = 64): Int

Decides up to max queued client Initials: a duplicate of a connection created meanwhile is routed to it; a forged or expired Retry token is refused with INVALID_TOKEN; a full accept queue is refused with CONNECTION_REFUSED; the hard limits maxConnections and maxConnectionsPerIp drop; then QuicEndpointConfig.admission decides. Returns the number of connections created. The runtime calls it after every receive batch; what it leaves waits for the next one.
