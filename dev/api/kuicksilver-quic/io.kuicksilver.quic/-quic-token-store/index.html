QuicTokenStore

interface QuicTokenStore(source)

Where a client keeps the address-validation tokens servers send in NEW_TOKEN frames (RFC 9000 section 8.1.3), so that its next connection to the same server skips the Retry round trip and the server's anti-amplification limit (QuicClientConfig.Builder.tokenStore; off by default).

Privacy. A token is an identifier the server issued to this client: presenting it on a later connection tells the server that both connections come from the same client, even from another network (RFC 9000 section 8.1.3 lets a client trade that linkability for the saved round trip). Keep a store only where the server may link connections anyway (a logged-in app talking to its own backend); a store that outlives a network change or a user switch links them too.

The endpoint calls take before each connection to the server named by the key, in the coroutine that calls connect, and uses what it gets once; it calls put on the endpoint loop for each token the server sends (at most eight per connection, each at most 1024 bytes). Neither should block: a call that has not finished after 250 ms is cancelled and the connection goes on without the token (logged once per endpoint loop), so connect never waits longer for the store. An exception from either is logged and the connection goes on without a token. Keys are "<server name>:<port>", or "<IP literal>:<port>" without a server name (an IPv6 literal in brackets), so a token is never sent to another server name on the same address (RFC 9000 section 8.1.3: "MUST NOT include a token that is not applicable to the server").
