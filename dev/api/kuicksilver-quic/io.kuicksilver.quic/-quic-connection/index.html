peerSupportsDatagrams
Link copied to clipboard
abstract val peerSupportsDatagrams: Boolean

True once the peer's transport parameters are known and advertise max_datagram_frame_size above 0: the peer supports DATAGRAM frames (RFC 9221 section 3), however small its limit. sendDatagram answers DatagramUnsupportedReason.PeerDoesNotSupport exactly when this is false; with a small limit it answers DatagramSendResult.TooLarge for what does not fit. maxDatagramSize cannot tell these apart: it is 0 without support, with a limit of 2 (room for an empty datagram only) and with a limit of 1 (room for none: an empty datagram too is TooLarge(max = 0); peerSupportsDatagrams && maxDatagramSize.value == 0 tells it). False before the handshake has delivered the parameters (or, for 0-RTT, the remembered ones).

addPath
Link copied to clipboard
abstract suspend fun addPath(io: DatagramIo): QuicPath

Client only: a new path to the server through io (a second socket), unvalidated. Before the handshake is confirmed it waits for the confirmation (it follows completion within a round trip) and throws the connection's QuicException.ConnectionLost if it ends first; MigrationRefusedException (an IllegalStateException) when the server advertised disable_active_migration or uses zero-length connection IDs (a new path would be linkable to the old one, RFC 9000 section 9.5), IllegalStateException beyond four paths. The socket is closed then, as on any other failure or cancellation before the path took it over.

Returns once the handshake completed (RFC 9001 section 4.1.1); throws the connection's QuicException.ConnectionLost when it failed. A server connection accepted before completion (0-RTT) is authenticated only from here on: act on input that is not safe to repeat only after this returns. abstract suspend fun migrate(newIo: DatagramIo): PathEvent.Changed

Client only: addPath + QuicPath.probe + QuicPath.switchTo. A failed validation throws PathValidationException (an IllegalStateException, "path validation failed"), leaves the connection where it was and closes newIo; its reason is PathFailureReason.NoSpareConnectionId when the server gave no spare connection ID in time (right after the handshake the probe waits for one, see QuicPath.probe). sendDatagram
Link copied to clipboard
abstract suspend fun sendDatagram(data: ByteArray, policy: DatagramPolicy = DatagramPolicy.DropOldest)

Queues a datagram (RFC 9221). Under DatagramPolicy.Reject it suspends while the send queue is full; under DropOldest / LatestWins it never suspends, and what is buffered for the loop is bounded too (at most twice QuicConfig.datagramSendQueue): a burst that outruns the loop loses its oldest datagrams even on an idle network, so send a burst you cannot lose under Reject. Throws QuicException.DatagramTooLarge above maxDatagramSize and QuicException.DatagramUnsupported when either side has datagrams off.

open suspend fun sendDatagram(data: ByteArray, policy: DatagramPolicy, priority: StreamPriority)

sendDatagram scheduled by RFC 9218 urgency: the datagram does not go ahead of stream data of strictly more urgent streams (priority's urgency is higher than theirs, or they are the HTTP/3 control and QPACK streams), while stream data of the same or a lower urgency waits behind it. Datagrams still leave in the order they were queued. Without a priority (the overloads above) a datagram goes ahead of every stream. Implementations outside this library need not override it: the default ignores priority.
