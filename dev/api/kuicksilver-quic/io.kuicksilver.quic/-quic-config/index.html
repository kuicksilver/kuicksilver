initialRtt
Link copied to clipboard
val initialRtt: Duration

RTT assumed before the first sample (RFC 9002 section 6.2.2), in (0, 10 s]: the first PTO is 3 x this (999 ms at the 333 ms default, then 2 s, 4 s ...), and a path validation lasts at least 6 x this (RFC 9000 section 8.2.4). Lower recovers a lost first flight sooner at the price of spurious retransmissions on slow links; see docs/guide/quic.md, "Configuration". A client endpoint that already finished a connection to the same server address on its own socket starts from that connection's final smoothed RTT instead (RFC 9002 section 6.2.2).

keepAlive
Link copied to clipboard
val keepAlive: Duration?

PING interval while the application is quiet; null disables keep-alive. Positive and finite, and at most 3/4 of maxIdleTimeout unless that is Duration.ZERO (then only the peer's idle timeout applies, and keep-alive is what holds the connection). PINGs go out at least every half of the effective idle timeout, so a peer with a shorter timeout than this interval does not close the connection (as quic-go's KeepAlivePeriod).
