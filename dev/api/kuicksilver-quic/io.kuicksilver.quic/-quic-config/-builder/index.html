followPreferredAddress
Link copied to clipboard
var followPreferredAddress: Boolean

Default true (RFC 9000 section 9.6: a client SHOULD). A client whose server advertises a preferred address of the family it uses validates a path there once the handshake is confirmed, with the server's sequence-1 connection ID, and moves the connection there when the server answers (PathChangeReason.PreferredAddress); the original path then closes. Until then only probes go there, and a failed validation leaves the connection where it is. A public server's preferred address on a loopback, link-local or private address, or any unspecified, multicast or broadcast one, is ignored (threat-model 3.14). The server's disable_active_migration does not stop the move, and after it the client may migrate. False stays put.

pmtudIcmpHints
Link copied to clipboard
var pmtudIcmpHints: Boolean

Default true. Where the socket reports them, an ICMP Packet Too Big (Linux and Android with the accelerated socket) and a send the kernel refused as too large (EMSGSIZE, every accelerated socket) speed up DPLPMTUD as hints (RFC 8899 section 4.6, RFC 9000 section 14.2.1): a Packet Too Big must quote one of this connection's packets on its active path and report at least 1200 bytes of payload, at most 64 a second per endpoint are looked at, and it only ends larger probes early or drops the MTU to 1200 provisionally: a probe of the old size that is acknowledged restores it and suspends Packet Too Big processing for 600 s. Without such a socket it changes nothing; false ignores them.
