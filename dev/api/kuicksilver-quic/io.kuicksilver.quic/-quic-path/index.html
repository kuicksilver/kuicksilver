QuicPath

interface QuicPath(source)

One network path of a QuicConnection (RFC 9000 section 9): a local socket and the peer address it talks to. The first path is the one the connection was established on; a client adds more with QuicConnection.addPath, validates them with probe and moves the connection with switchTo. A server only observes paths its client moves to.

probe
Link copied to clipboard
abstract suspend fun probe(): Boolean

Sends a PATH_CHALLENGE and suspends until the path is validated (true) or gives up after the validation timeout (false). A probe needs a connection ID from the peer that no other path used (RFC 9000 section 9.5): right after the handshake the peer's NEW_CONNECTION_ID frames may still be on their way, so the probe first waits up to the validation timeout for one, and fails with PathFailureReason.NoSpareConnectionId (PathEvent.Failed.reason) if none comes.

switchTo
Link copied to clipboard
abstract suspend fun switchTo()

Moves the connection to this validated path; the previous path stays as a fallback until it is closed. IllegalStateException when the path is not validated, or while no unused connection ID of the peer is left for it (RFC 9000 section 9.5: "An endpoint MUST NOT reuse a connection ID when sending from more than one local address"; the peer replaces a retired one within a round trip).
