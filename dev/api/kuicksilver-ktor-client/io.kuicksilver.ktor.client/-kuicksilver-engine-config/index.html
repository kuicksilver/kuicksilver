connectionAttemptDelay
Link copied to clipboard
var connectionAttemptDelay: Duration

Happy Eyeballs (RFC 8305) for the engine's connects, TCP and QUIC (docs/guide/ktor.md, "Happy Eyeballs"): a host name's IPv6 and IPv4 addresses are asked for separately and raced as they arrive, sorted by RFC 6724 with the two families alternating; the next address is tried when this delay has passed since the last attempt started or as soon as an attempt failed (never within 10 ms of the last start), and the first connection wins (the others are cancelled or closed). The same delay staggers HTTP/3's QUIC handshakes over the addresses. 250 ms by default, as RFC 8305 section 8 recommends; 100 ms (the Minimum Connection Attempt Delay) to 2 s (the Maximum) is allowed, or Duration.INFINITE to try one address after another. Any other value fails the engine's creation with IllegalArgumentException. connectTimeout bounds all attempts together.

connectTimeout
Link copied to clipboard
var connectTimeout: Duration

Connect timeout when HttpTimeout sets none (TCP + TLS, or the QUIC handshake; the name resolution and the wait for a pool slot share it). A WebSocket over HTTP/1.1 is connecting until the server answers its opening handshake (RFC 6455 section 4.1): that answer must arrive within the same timeout, counted from the moment the WebSocket has its connection, else the WebSocket fails with ConnectTimeoutException. Its wait for another WebSocket to the same address to finish connecting counts against neither.

connectUdpProxy
Link copied to clipboard
var connectUdpProxy: ConnectUdpProxy?

A CONNECT-UDP proxy (RFC 9298, MASQUE) for HTTP/3, or null (the default) for none. An https request it applies to goes over HTTP/3 inside a UDP tunnel through it, whatever proxy or proxyResolver say (they keep deciding for the requests it does not apply to): never over HTTP/1.1 or HTTP/2, and never directly, since either would leave the proxy out. So such a request fails, with the reason, when the origin has no HTTP/3, when the proxy refuses the tunnel (Http3Exception.ConnectRejected with its proxy-status), under http3 { discovery = H1Only } or while http3Allowed says no (UnsupportedOperationException). Alt-Svc is neither used nor learned for it, and the origin's name is resolved by the proxy, not here. WebTransport refuses such URLs unless http3 { webTransportIgnoresConnectUdpProxy }. docs/guide/ktor.md, "HTTP/3 through a CONNECT-UDP proxy".

dns
Link copied to clipboard
var dns: Dns

Resolves host names to the addresses the engine connects to, over TCP and QUIC, with Happy Eyeballs (RFC 8305) on what it answers: Dns.System (the default: the system's resolver, as before 0.3.0) or your own, after OkHttp's Dns, for another DNS server (DNS over HTTPS), fixed addresses or a policy of your own; Dns.blocking adapts a blocking one, and a FamilyDns answers each address family on its own (RFC 8305 section 3). Its lookup is part of connecting (connectTimeout bounds it), it never gets address literals, it is asked for an HTTP proxy's name but never for the origin's behind it, and its answers never stand in for the host name in TLS: SNI and the certificate check use the URL's host. See Dns for the whole contract and docs/guide/ktor.md, "Name resolution".

Servers known to handle HTTP/1.1 (RFC 9112 section 6.1: "such knowledge might be in the form of specific user configuration"): a request with Transfer-Encoding (a body of unknown length, or a transfer coding the application applied) goes to them chunked at once, without the OPTIONS the engine otherwise sends first to a server it has not seen answer with HTTP/1.1 nor pick ALPN http/1.1. maxConnectionLifetime
Link copied to clipboard
var maxConnectionLifetime: Duration

Age after which a connection takes no new requests: a pooled HTTP/1.1 connection is closed instead of reused, and new HTTP/2 and HTTP/3 requests go to a new connection while the old one finishes its requests and then closes. Infinite by default, as in OkHttp and CIO; a finite value spreads load after DNS or load-balancer changes.

maxConnectionsCount
Link copied to clipboard
var maxConnectionsCount: Int

TCP connections (HTTP/1.1 and HTTP/2) open at once across all routes, idle ones included (CIO's maxConnectionsCount, the same default 1000). A request beyond it waits, in FIFO order, within the connect timeout; when other routes hold idle connections, the oldest one is closed to make room instead. HTTP/3 multiplexes and is limited per origin instead.

maxConnectionsPerRoute
Link copied to clipboard
var maxConnectionsPerRoute: Int

TCP connections (HTTP/1.1 and HTTP/2) open at once to one route (scheme, host, port and proxy), idle ones included (CIO's endpoint.maxConnectionsPerRoute, the same default 100); further requests to it wait in FIFO order within the connect timeout, failing with ConnectTimeoutException when no connection frees up in time. An HTTP/2 connection counts once, however many requests it carries; a second one opens only when the first has no stream left under the server's SETTINGS_MAX_CONCURRENT_STREAMS.

pacFullWebSocketUrl
Link copied to clipboard
var pacFullWebSocketUrl: Boolean

Whether a proxy auto-configuration (PAC) script the system settings name gets a wss:// WebSocket's whole URI with its resource name (path and query), as RFC 6455 section 4.1 asks, on Apple platforms and Windows (ProxyResolvers.System); the script must be given inline in the settings (Apple), by an https:// URL or by a local file: URL (file:///…; one with a host, file://srv/share/p.pac, is fetched over SMB and does not count). Off by default: every script gets wss://host[:port]/ only, as Chrome, Firefox and Android give https and wss URLs to PAC scripts, since a script can send what it is given out through dnsResolve (CVE-2016-3763, CVE-2016-5134). A script found by WPAD (automatic detection) or fetched over plain http:// never gets more than that, whatever this says: whoever answers on the local network writes it. ws:// URIs reach every script whole, http and https ones as their origin. On Apple platforms the PAC URL CFNetwork reports must equal the settings' string exactly; one written otherwise gets the origin. docs/guide/ktor.md, "Proxies".

proxyCredentials
Link copied to clipboard
var proxyCredentials: ProxyCredentials?

Credentials for the explicit proxy only: a proxy a proxyResolver returns carries its own (ResolvedProxy.credentials: the user info of https_proxy and the like, or what your resolver gives ResolvedProxy.http(host, port, credentials)), and these are never sent to it. SOCKS5 username/password (RFC 1929), offered to a SOCKS5 proxy and sent only when it picks that method, or Proxy-Authorization: Basic on an HTTP proxy's CONNECT and absolute-form requests, sent with the first request (no 407 round trip) unless the request sets its own Proxy-Authorization. Off the JVM the proxy URL's user info (http://user:password@proxy:3128) wins over these. Null (the default) for none. Both go in clear to an http:// or SOCKS5 proxy (RFC 1929 section 5, RFC 7617 section 4) and only inside TLS to an https:// one (after its certificate verified), never to the origin, and never into the engine's logs or events. On the JVM and Android the proxy is a java.net.Proxy, which has no scheme: ProxyBuilder.http(Url("https://...")) there makes an HTTP proxy on port 443, which the engine refuses (every request fails with UnsupportedOperationException) rather than send the CONNECT and these credentials in clear to it; name an https:// proxy with a proxyResolver (ResolvedProxy.https) or the environment, and a plain proxy on port 443 with a resolver's ResolvedProxy.http. A SOCKS5 proxy with an empty password (here or in its URL) fails the engine's creation with IllegalArgumentException: RFC 1929 section 2 gives the password 1 to 255 octets (curl and Go send an empty one anyway, outside the protocol).

proxyResolver
Link copied to clipboard
var proxyResolver: ProxyResolver

Where the proxy for a request comes from when proxy is not set (an explicit proxy always wins): ProxyResolvers.System (the default: the platform's proxy settings), ProxyResolvers.Environment (https_proxy, no_proxy...), ProxyResolvers.None for direct connections, or your own ProxyResolver. A request through a proxy uses TCP only (HTTP/1.1, or HTTP/2 with the origin inside a tunnel) and neither uses nor learns Alt-Svc; localhost and loopback addresses always connect directly with the built-in resolvers. docs/guide/ktor.md, "Proxies".

proxyTls
Link copied to clipboard
var proxyTls: TlsConfig.Builder.() -> Unit?

The TLS settings of connections to an https:// proxy (ResolvedProxy.https: TLS to the proxy itself), separate from the origin's. Null (the default) takes the origin's: the tls block over trust, then that trust without what names the origin (a TrustConfig.ExpectedName gives way to its base, a TrustConfig.Pinned to its base: the proxy has another name and another key), and no client certificate (identity is the origin's and is not shown to the proxy). A block starts from that same trust and no identity and may set anything (trust, identity for a proxy that wants a client certificate, versions...). Whatever it says, the server name, which is both SNI and the name the certificate is verified against (RFC 9525), is the proxy's host and ALPN offers http/1.1 only; set after the block. The origin's TLS inside the proxy's tunnel keeps trust, identity and tls, as without a proxy. docs/guide/ktor.md, "Proxies".

webSocketMaxMessageSize
Link copied to clipboard
var webSocketMaxMessageSize: Long

The largest WebSocket message, and so frame, the client takes from a server, in bytes (RFC 6455 section 10.4: an implementation "SHOULD impose a limit on frame sizes and the total message size after reassembly"); 16 MiB by default, as PerMessageDeflate's maxInflatedMessageSize. A frame whose header claims more, or that takes its message past it, closes the connection with 1009 (message too big) before any of its payload is read; a compressed message is held to the smaller of this and the extension's limit, counted inflated. Over HTTP/1.1, HTTP/2 and HTTP/3 alike; Ktor's WebSockets { maxFrameSize } applies on top of it. Less than 1 fails the engine's creation with IllegalArgumentException.
