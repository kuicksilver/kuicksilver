System

val System: ProxyResolver(source)

The platform's proxy settings: on the JVM and Android java.net.ProxySelector.getDefault() (system properties, java.net.useSystemProxies, Android's per-network proxy and PAC); on Apple platforms the system's proxy settings (CFNetworkCopyProxiesForURL, with its exceptions list); on Windows the user's Internet settings (WinHttpGetIEProxyConfigForCurrentUser, with its bypass list); on Linux, which has no system API, Environment. A proxy auto-configuration is run on Apple platforms by the engine itself (a PAC URL or script of the settings, or WPAD when they say "auto discover"; the script downloaded by the engine and run on JavaScriptCore, sandboxed and time-limited) and on Windows by WinHTTP (automatic detection, WPAD, or a PAC URL, WinHttpGetProxyForUrl); a lookup waits for it at most 5 seconds (on Windows a WinHTTP call still running then is left to end on its own, and its answer is dropped). The script gets a ws:// URI whole, with its resource name (RFC 6455 section 4.1); wss and https as their origin only (wss://host[:port]/), as browsers give them, since a script from WPAD could send a path's tokens out; http as its origin too, because the engine keeps answers per scheme, host and port (browsers keep an http path). KuicksilverEngineConfig.pacFullWebSocketUrl gives the settings' own script (inline, or from an https or local file URL; never WPAD's) a wss:// URI whole. A script that cannot be fetched or run in that time means the next setting (on Windows the fixed proxy, if any) or a direct connection, and the engine logs one warning. On Windows a WPAD detection that found no script is remembered for 5 minutes (detection is not run again in that time).
