FileAltSvcStore
Link copied to clipboard
class FileAltSvcStore(path: Path, clock: () -> Long = { getTimeMillis() }) : AltSvcStore

An AltSvcStore kept in one text file (alternatives survive a restart, so the first request after a cold start can already use HTTP/3). One record per line, tab-separated: origin, protocol, host (empty when the origin's), port, expiry in epoch milliseconds, 1 when persist=1. The file is read once at construction: it is input like a header, so every field is checked again (the origin's https://host:port form, the protocol token, the host as the Alt-Svc parser takes it, the ports, the expiry, the persist flag) and a record failing a check is dropped, as is an expired one; at most 1000 origins of 8 alternatives are kept, and of a file over 8 MiB only the records in its first 8 MiB are read (a full store takes less than that). The engine also checks each entry it uses as it checks a header's. The file is rewritten after every change through a uniquely named temporary file and an atomic move, so a crash leaves either the old or the new content (on Android API 24-25, which lacks java.nio.file, the move is a java.io.File.renameTo, atomic on one filesystem). A store that cannot be written keeps working in memory; the first failed write is logged as a warning. A repeated header always replaces the alternatives in memory (RFC 7838 section 3); it is not written when it only moves the expiry later by less than half the new lifetime. The store keeps at most 1000 origins, dropping the least recently used (threat-model 3.18). Used by the engine, the file is written after the engine's lock is released. Calls are serialized by the engine's lock; two engines sharing one file would overwrite each other's changes.

Http2ClientConfig
Link copied to clipboard
class Http2ClientConfig

HTTP/2 on the TCP path (RFC 9113; docs/guide/ktor.md, "HTTP/2"): every https:// connection over TCP offers h2 and http/1.1 in ALPN, and a server that picks h2 gets one multiplexed connection per route instead of up to maxConnectionsPerRoute HTTP/1.1 connections. An http:// request uses HTTP/1.1, unless its origin is listed in priorKnowledge (h2c, HTTP/2 over cleartext TCP). A wss:// WebSocket goes over HTTP/2 (RFC 8441, Extended CONNECT) on a connection to its origin that is there already and whose server allows it (SETTINGS_ENABLE_CONNECT_PROTOCOL); otherwise it opens a connection of its own that offers http/1.1 only, as in 0.2 (docs/guide/ktor.md, "WebSockets over HTTP/2"). HTTP/3 is unaffected, and so is its kill switch (http3 { http3Allowed } turns HTTP/3 off, not HTTP/2). A tls block that allows TLS 1.2 (versions = TlsVersions.Tls12And13) offers h2 as well (RFC 9113 section 9.2): over TLS 1.2 renegotiation stays refused, and a server that asks for one (a HelloRequest) ends the connection with a connection error of type PROTOCOL_ERROR (section 9.2.1); the TLS 1.2 suites are ECDHE with an AEAD only, none of them prohibited by section 9.2.2.

KuicksilverEventListener
Link copied to clipboard
abstract class KuicksilverEventListener

Hears what the client engine does with each call (docs/guide/ktor.md, "Observability"), in the manner of OkHttp's EventListener: set it with engine { eventListener = ... }. Every method has an empty default; override the ones you need. The order for one call is callStart, then for each attempt the protocol decision (protocolSelected, with raceEnded, altSvcUsed, fallback and retry where they apply), the name lookups it makes (dnsStart and dnsEnd, before the connection they serve; usually none when the request reuses a pooled connection, except that a WebSocket's keys are looked up before the pool is asked, and an HTTP/3 request whose origin has a connection under another name (its host and an alternative) resolves first to decide whether to share it) and connectionAcquired, and finally callEnd or callFailed; connectionReleased follows when the call's response is done with.

ProxyCredentials
Link copied to clipboard
class ProxyCredentials(val user: String, val password: String)

A user name and password for a proxy: SOCKS5 username/password authentication (RFC 1929) or HTTP Basic (Proxy-Authorization, RFC 9110 section 11.7.2, RFC 7617). To an http:// proxy and a SOCKS5 one they travel in clear (RFC 7617 section 4, RFC 1929 section 5); to an https:// proxy (ResolvedProxy.https) only inside TLS with the proxy, once its certificate has been verified. toString leaves the password out, and hashCode depends on the user name only. For SOCKS5 the password must have 1 to 255 bytes in UTF-8: RFC 1929 section 2 gives PASSWD 1 to 255 octets (curl and Go's x/net/proxy send an empty one with PLEN 0, which the RFC does not allow), so a SOCKS5 proxy configured with an empty password fails at once with IllegalArgumentException (the engine's creation for its proxy, ResolvedProxy.socks5 for a resolver's). An HTTP proxy takes an empty password (RFC 7617).

A proxy refused or failed the request's connection: a SOCKS5 reply other than "succeeded" (replyCode is its REP field, RFC 1928 section 6), a SOCKS5 authentication the proxy rejected (replyCode null), a status other than 2xx in answer to an HTTP CONNECT (replyCode is the status, 407 when the proxy wants credentials; the engine does not repeat the CONNECT), or, as ProxyTlsException, a failed TLS handshake with an https:// proxy. Chooses the proxy for each request the engine's explicit proxy does not cover: engine { proxyResolver = ... }. proxyFor returns null for a direct connection. class ProxyTlsException(message: String, cause: Throwable) : ProxyException

The TLS handshake with an https:// proxy (ResolvedProxy.https) failed: its certificate did not verify against the proxy's name or trust (KuicksilverEngineConfig.proxyTls), it refused the handshake, or it closed the connection during it. cause is what the TLS layer reported (a TlsException, whose Verify subclass says why the certificate was rejected, or an IOException for a connection that ended). clearAlternativeServices
Link copied to clipboard
suspend fun HttpClient.clearAlternativeServices(origin: Url? = null): Boolean

Forgets what this client learned about the alternative services of origin (any URL of it: https://host:port), or of every origin when origin is null: the cached Alt-Svc alternatives in Http3ClientConfig.altSvcStore (persistent ones too, and from the store file of a FileAltSvcStore before this returns), the alternatives marked broken, and the RTTs kept for the HTTP/3 head start; without an origin also the networks where QUIC was seen working. RFC 7838 section 9.4: "In a user agent, any alternative service information MUST be removed when origin-specific data is cleared (typically, when cookies (RFC 6265) are cleared)": call it wherever the application clears cookies or other site data. Open HTTP/3 connections are not closed (closeHttp3Connections() does that); the next Alt-Svc the origin sends is learned again. Returns true when everything asked for was removed; false when the client's engine is not Kuicksilver (nothing was done), or when, without an origin, the AltSvcStore does not implement AltSvcStore.clear: then only the origins seen since the client started were removed from it (a warning is logged) and the application should clear the store's own backing data, or remove the origins it knows with origin, to meet section 9.4.

closeHttp3Connections
Link copied to clipboard
suspend fun HttpClient.closeHttp3Connections()

Takes every HTTP/3 connection of this client out of use (docs/guide/ktor.md, "Turning HTTP/3 off remotely"): each established pooled connection gets a GOAWAY and no further request; the next request opens a new connection (when HTTP/3 is allowed, see Http3ClientConfig.http3Allowed) or goes over HTTP/1.1. Calls already running on them finish, and each closes with H3_NO_ERROR once its last call is done (an idle one at once). A connection still being set up serves the requests already waiting for it, then closes. Every open WebTransport session gets WT_DRAIN_SESSION and its connection a GOAWAY: the server is asked to wind the session down; the session itself stays open until either side closes it. Returns once the GOAWAYs are written (each waits at most 5 seconds). Does nothing when the client's engine is not Kuicksilver.

followDefaultNetwork
Link copied to clipboard
fun Http3ConnectionMigration.Companion.followDefaultNetwork(connectivity: ConnectivityManager): Http3ConnectionMigration

HTTP/3 connections follow the device's default network (Android): each connection gets a NetworkMigrator over ConnectivityManager.defaultNetworks (one system callback per manager, shared by every connection) that opens the socket for a new network bound to it (Network.bindSocket) and migrates there, as QuicConnection.followDefaultNetwork does. Needs ACCESS_NETWORK_STATE, which the library manifest declares. The same source is the engine's network (Http3ConnectionMigration.networks) unless networkId is set: a new default network resets the broken marks of Alt-Svc alternatives and drops those without persist=1. The engine also takes the network's NAT64 prefix from connectivity (LinkProperties.getNat64Prefix, API 30), for Happy Eyeballs on an IPv6-only network without 464XLAT. Get the manager from the application's context (context.applicationContext.getSystemService(ConnectivityManager::class.java)), not an Activity's, which the engine would keep alive.

fun Http3ConnectionMigration.Companion.followDefaultNetwork(): Http3ConnectionMigration

HTTP/3 connections follow the system's default network (iOS, macOS): each connection gets a NetworkMigrator over nwPathUpdates (one NWPathMonitor shared by every connection) that opens the socket for a new path bound to its interface (IP_BOUND_IF) and migrates there, as QuicConnection.followDefaultNetwork does; it also replaces a socket iOS reclaimed while the app was suspended. Unless networkId is set, the default path is also the engine's network (Http3ConnectionMigration.networks), identified by its interface, gateways and the interface's addresses (compared in memory, never stored or logged): a new network, also one on the same interface, resets the broken marks of Alt-Svc alternatives, drops those without persist=1 and flushes the HTTPS record cache.

neverIndex
Link copied to clipboard
fun HttpRequestBuilder.neverIndex(vararg names: String)

Sends this request's fields named names (any case) as literals never indexed: over HTTP/2 (RFC 7541 section 6.2.3) and over HTTP/3 with QPACK's 'N' bit (RFC 9204 section 4.5.4). The encoder neither adds them to the dynamic table nor refers to an entry for them, and an intermediary has to keep that representation (RFC 7541 section 7.1.3, RFC 9204 section 7.1.3). priority
Link copied to clipboard
fun HttpRequestBuilder.priority(urgency: Int = 3, incremental: Boolean = false)

Gives this request an RFC 9218 priority: urgency 0 (most urgent) to 7, and whether its response may be incrementally interleaved with others of the same urgency. Over HTTP/3 the engine sends it as the priority field (none for the default, u=3 non-incremental) and schedules the request's own stream with it; a WebSocket over HTTP/3 carries it too. Over HTTP/2 the same, and until the server's SETTINGS say it ignores them, the request's HEADERS also carry an RFC 7540 weight from the urgency (RFC 9218 section 2.1.1). Over HTTP/1.1 only the Priority field is sent. A Priority header set on the request is dropped in its favour, so the server sees one signal. Without this call a Priority header is sent as it is.

updatePriority
Link copied to clipboard
suspend fun HttpResponse.updatePriority(urgency: Int, incremental: Boolean): Boolean

Sends a new priority for this response (a PRIORITY_UPDATE frame, RFC 9218 section 7) and applies it to the request's own stream; the server reschedules the rest of the response unless it set a priority of its own. Over HTTP/2 the signals follow section 2.1.1: PRIORITY_UPDATE unless the server's SETTINGS left SETTINGS_NO_RFC7540_PRIORITIES at 0, and an RFC 7540 PRIORITY frame unless they said 1 (both before those SETTINGS). True when a signal was sent; false over HTTP/1.1, which has no such signal, once the call is over or its body was read to the end, and when the connection is gone.

webTransport
Link copied to clipboard
suspend fun HttpClient.webTransport(urlString: String, protocols: List<String> = emptyList(), headers: Http3Headers = Http3Headers.Empty): WebTransportSession

Opens a WebTransport session (draft-ietf-webtrans-http3-16) to urlString, an https URL. Sessions share the engine's pooled HTTP/3 connection to the URL's host and port with each other and with requests (RFC 9114 section 3.3: one connection per address and port), as long as the server allows it: with WebTransport flow control on both sides (draft-16 section 5.1) a connection carries up to http3 { settings.webTransportMaxSessions } sessions (4 by default) and as many as the server accepts (section 5.2: a session it refuses with H3_REQUEST_REJECTED is opened again on another connection to the same server, which the next sessions share too, unless none of this client's sessions was on the refusing connection: that is the server's rate, and the refusal is thrown as io.kuicksilver.http3.Http3Exception.RequestNotProcessed); without flow control a connection carries one session, and each further one gets a connection of its own. A pooled connection that is not WebTransport-capable (opened for requests without WebTransport's SETTINGS and reset_stream_at) is replaced by one that is, which carries the origin's requests from then on; the old one finishes its requests and closes. A connection stays open while a session or a request uses it, and then idles as any pooled connection does; an extra connection a server's limit made closes with its last session. protocols are offered in WT-Available-Protocols; headers go with the CONNECT (an origin, for a server that checks it).
