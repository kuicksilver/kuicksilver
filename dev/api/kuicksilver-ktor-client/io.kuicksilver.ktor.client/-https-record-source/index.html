HttpsRecordSource

sealed interface HttpsRecordSource(source)

Where the client engine looks up HTTPS resource records (RFC 9460) for an origin in Http3DiscoveryMode.Auto (Http3ClientConfig.httpsRecords; docs/guide/ktor.md, "HTTPS records"). A record that names h3 in its alpn lets the first request to the origin race HTTP/3 against TCP at once, without waiting for an Alt-Svc header. The engine is an SVCB-optional client (RFC 9460 section 3): a lookup that fails or answers late leaves the request on the path it would have taken without records.

Exchange
Link copied to clipboard
class Exchange(val secure: Boolean = false, val exchange: suspend (query: ByteArray) -> ByteArray) : HttpsRecordSource

Lookups through exchange: it gets a DNS query in wire format (RFC 1035 section 4.1, ID 0 and RD set, as RFC 8484 section 4.1 asks for DNS over HTTPS) and returns the response in wire format, for example the body of a POST to a DoH server with Content-Type: application/dns-message. The engine has no DoH client of its own. An exchange that throws, or returns something that is not the response to the query, counts as a failed lookup; so does a response over 65535 bytes (RFC 8484 section 6: "This media type restricts the maximum size of the DNS message to 65535 bytes").

ProtectedSystem
Link copied to clipboard
class ProtectedSystem(val isProtected: () -> Boolean) : HttpsRecordSource

The operating system's resolver, as System, whose answers are cryptographically protected whenever isProtected says so: then a failed lookup abandons the request (RFC 9460 section 3.1), as with Exchange(secure = true). Called once per request, on the call's coroutine; it must be quick, and one that throws counts as false. On Android HttpsRecordSource.followingPrivateDns(connectivity) builds one that reports Android's strict Private DNS (DNS over TLS with a configured server). On Apple platforms, Linux and Windows no public API tells whether the system's DNS is encrypted: give a check of your own (an MDM profile you deploy, say) or use System.

System

data object System : HttpsRecordSource

The operating system's resolver, so the lookups follow the system's DNS settings (Private DNS on Android, the scoped resolvers of macOS and iOS). Android asks DnsResolver.rawQuery from API 29; below API 29, and on platforms where the system resolver cannot be asked for HTTPS records yet, every lookup counts as failed and requests behave as with Off (docs/guide/ktor.md lists the platforms).
