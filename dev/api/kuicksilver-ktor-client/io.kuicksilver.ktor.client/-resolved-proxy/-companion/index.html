An HTTP proxy at host:port, spoken to in plain TCP: its CONNECT and absolute-form requests, and credentials with them, cross the network in clear (RFC 7617 section 4); use https for a proxy that speaks TLS.

https
Link copied to clipboard
fun https(host: String, port: Int, credentials: ProxyCredentials? = null): ResolvedProxy

An HTTPS proxy at host:port: TLS to the proxy itself (an https:// proxy URL), then the same requests as http inside it, so credentials and the CONNECT's target never cross the network in clear. The proxy's certificate is verified against host (a DNS name, or an IP address as an IP-ID; RFC 9525), which is also its SNI unless it is an IP address (RFC 6066 section 3), with KuicksilverEngineConfig.proxyTls (by default the engine's own trust without the origin's pins and expected name); ALPN offers http/1.1 only. A request to an https origin runs the origin's TLS inside the tunnel (TLS in TLS), verified as without a proxy. host goes through the engine's dns.

fun socks5(host: String, port: Int, credentials: ProxyCredentials? = null, remoteDns: Boolean = true): ResolvedProxy

A SOCKS5 proxy at host:port; remoteDns true (socks5h) lets it resolve the origin's name. Fails with IllegalArgumentException for credentials whose password is empty or longer than 255 bytes (RFC 1929 section 2: PASSWD has 1 to 255 octets).
