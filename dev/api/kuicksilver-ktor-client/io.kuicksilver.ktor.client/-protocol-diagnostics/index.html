ProtocolDiagnostics

class ProtocolDiagnostics(source)

Which protocol served a call and, when it was not HTTP/3, why (docs/guide/ktor.md, "Why did this request not use HTTP/3?"). The engine attaches one to every response it returns: read it with HttpResponse.kuicksilverDiagnostics. A call that fails has no response and so none; its exception says what happened (when the HTTP/3 and HTTP/1.1 setups both failed, the HTTP/1.1 failure is thrown with the HTTP/3 one in suppressed).

It lives as long as the response (it is one of the call's attributes) and holds the HTTP/3 failure, if any, by reference; the engine keeps no copy of it.

The engine puts a new one into the request's attributes when the call reaches it, fills it while the call runs (code that reads KuicksilverDiagnosticsKey from the request before the response, a listener say, sees it incomplete) and removes it when the call fails. Read it from the response: a request built from an earlier one (Ktor's redirect copies the attributes with takeFrom) carries the earlier response's diagnostics until the engine replaces them, so a plugin that runs before the engine sees stale ones; and when an interceptor sends one request builder through the engine twice, each engine call gets its own object and the attributes keep the last.

var attempts: Int

How many attempts the engine made for the response: the first, plus one per repeat by the engine (a request the server did not process — GOAWAY, H3_REQUEST_REJECTED — or that this client's own closeHttp3Connections() stopped before it went out, each repeated on a new connection; a stale pooled HTTP/1.1 connection; a 417 to Expect: 100-continue), plus one for the fallback to HTTP/1.1 when HTTP/3 had tried the request (not when the HTTP/3 connection could not be set up or its handshake failed: then HTTP/1.1 is the first attempt). Repeats inside the HTTP/3 layer on the same connection — a 0-RTT request sent again after its early data was rejected, or after a 425 Too Early — are not counted.

fallback

var fallback: FallbackReason?

Why the call did not go over HTTP/3; null when it did. See FallbackReason for what each value means and what to check. A call over HTTP/2 has the reason HTTP/3 was not used, as one over HTTP/1.1. The one exception is FallbackReason.H2Refused: the call went over HTTP/1.1 because the server refused HTTP/2, and the reason HTTP/3 was not used appears in the log line as h3Fallback=.
