Http2ClientConfig

class Http2ClientConfig(source)

HTTP/2 on the TCP path (RFC 9113; docs/guide/ktor.md, "HTTP/2"): every https:// connection over TCP offers h2 and http/1.1 in ALPN, and a server that picks h2 gets one multiplexed connection per route instead of up to maxConnectionsPerRoute HTTP/1.1 connections. An http:// request uses HTTP/1.1, unless its origin is listed in priorKnowledge (h2c, HTTP/2 over cleartext TCP). A wss:// WebSocket goes over HTTP/2 (RFC 8441, Extended CONNECT) on a connection to its origin that is there already and whose server allows it (SETTINGS_ENABLE_CONNECT_PROTOCOL); otherwise it opens a connection of its own that offers http/1.1 only, as in 0.2 (docs/guide/ktor.md, "WebSockets over HTTP/2"). HTTP/3 is unaffected, and so is its kill switch (http3 { http3Allowed } turns HTTP/3 off, not HTTP/2). A tls block that allows TLS 1.2 (versions = TlsVersions.Tls12And13) offers h2 as well (RFC 9113 section 9.2): over TLS 1.2 renegotiation stays refused, and a server that asks for one (a HelloRequest) ends the connection with a connection error of type PROTOCOL_ERROR (section 9.2.1); the TLS 1.2 suites are ECDHE with an AEAD only, none of them prohibited by section 9.2.2.

Offer HTTP/2 (true by default). False offers only http/1.1 in ALPN, as before 0.3.0: the switch for a server or middlebox whose HTTP/2 is broken.

pingInterval

var pingInterval: Duration

Sends a PING this often on every HTTP/2 connection and closes the connection when one is still unanswered at the next (OkHttp's pingInterval); its calls fail. Duration.INFINITE (the default) sends none. At least 100 ms.

priorKnowledge
Link copied to clipboard
var priorKnowledge: Set<HostPort>

The http:// origins (host and port, as in request URLs) whose server is known to speak HTTP/2 over cleartext TCP: their requests go over h2c with prior knowledge (RFC 9113 section 3.3), the client connection preface right after the TCP connect, without TLS, without ALPN and without Upgrade: h2c (deprecated by section 3.1, never sent). Empty by default: every other http:// request stays HTTP/1.1, and nothing is learned (a server that once spoke h2c is not assumed to again, section 3.3). The list is per origin on purpose (OkHttp's Protocol.H2_PRIOR_KNOWLEDGE turns a whole client to h2c): h2c is cleartext (CWE-319), so name only servers on a trusted network or behind a sidecar that protects the hop, as a TLS-terminating proxy, a service mesh or a gRPC back end are (docs/guide/ktor.md, "h2c").

var settings: Http2Settings

Our side of each HTTP/2 connection: windows, SETTINGS and the limits held against the server (threat model 3.23). Its maxConcurrentStreams is what we allow the server to open towards us, which a client never uses: a server's limit for our requests comes from its own SETTINGS.
