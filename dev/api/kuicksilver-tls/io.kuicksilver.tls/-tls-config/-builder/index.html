class Builder(val role: TlsRole)(source)

Mutable builder behind tlsConfig; every property starts at its safe default and build validates the combination. Not thread-safe; use one builder per configuration.

alpn
Link copied to clipboard
var alpn: List<String>

ALPN protocol IDs in preference order (RFC 7301), each 1..255 bytes of UTF-8 and at most 255 bytes together with one length byte each; default empty, which sends no ALPN extension. QUIC needs at least one (RFC 9001 section 8.1); a server that shares none with the client's offer fails the handshake with no_application_protocol. A server over TCP selects from the list without h3, which identifies HTTP/3 over QUIC only (RFC 9114 section 3.1); a list of h3 alone serves nothing there, and every TCP handshake ends with no_application_protocol.

alpnFallback
Link copied to clipboard
var alpnFallback: String?

Server, TLS over TCP: the protocol a client that sends no ALPN extension speaks (Netty's "fallback protocol"), e.g. http/1.1 for HTTP, whose h2 "over TLS MUST use protocol negotiation in TLS" (RFC 9113 section 3.3). Default null: such a client completes the handshake without ALPN, as with OpenSSL and Go's crypto/tls. Set, such a client completes it only where the protocols in effect for its connection name it: alpn, or the sniSelector answer's ServerTlsOverride.alpn; otherwise the handshake ends with no_application_protocol (120), the alert RFC 7301 section 3.2 gives a server that "supports no protocols that the client advertises" and RFC 9001 section 8.1 a QUIC server whose client negotiated none. The check runs at every ClientHello, a second one after HelloRetryRequest included (RFC 9846 section 4.2.2 lets a client change nothing else there, and a server is not told to compare), and again when the handshake completes. A present but malformed ALPN extension (RFC 7301 section 3.1: a non-empty list of non-empty names) gets decode_error (50) instead, as without the fallback. An empty list in effect (no ALPN) takes any client. QUIC ignores it: a QUIC client without ALPN is always refused (RFC 9001 section 8.1). The value is 1..255 bytes of UTF-8, and not h3, which identifies HTTP/3 over QUIC only (RFC 9114 section 3.1).

certificateCompression
Link copied to clipboard
var certificateCompression: Boolean

TLS certificate compression (RFC 8879), over TCP and QUIC; default true. A client offers brotli, then zlib, in its ClientHello and accepts the server's chain compressed with either; a server sends its chain compressed with the first of the client's algorithms it shares (compressed once per identity, when its context is built; a chain neither makes smaller goes out uncompressed) and offers the same two for client certificates when it asks for one. A peer without it gets and sends plain certificates. Over QUIC a smaller chain keeps more of the server's first flight inside the amplification limit before the client's address is validated (RFC 9000 section 8.1). TLS 1.3 only: a TLS 1.2 handshake ignores it. What a peer sends is held to the certificate list bound of 100 KiB: an announced length above it, data that does not decompress to exactly the announced length, or a decompression past it ends the handshake with bad_certificate (42); an algorithm that was not offered with illegal_parameter (47). False: no extension, and a compressed certificate from the peer is an unexpected_message (10). The algorithm the peer's chain came in: TlsConnection.peerCertificateCompression.

var genericAlerts: Boolean

Send every verification failure as handshake_failure instead of the specific alert, except a failed stapled OCSP check, which OpenSSL always ends with bad_certificate_status_response (113). Default false; true hides from the peer why it was rejected at the cost of harder diagnosis on its side. The local TlsException.Verify keeps the real reason either way.

handshakeTimeout
Link copied to clipboard
var handshakeTimeout: Duration

The deadline of a TLS-over-TCP handshake (TlsConnection, Socket.tls); default 10 seconds. A server counts the wait for the client's ClientHello in it. When it passes the handshake fails with TlsException.Protocol. Must be positive; Duration.INFINITE waits without a deadline. QUIC connections use their own QuicConfig.handshakeTimeout.

identity

var identity: TlsIdentity?

The chain and private key this side presents: required for a server unless sniSelector supplies one per connection, optional for a client (sent when the server asks for a certificate). Default null. A TlsIdentity.InMemory, or a TlsIdentity.Reloadable to replace the certificate at run time: each handshake then takes the identity current when the ClientHello arrives.

keyExchangeGroups
Link copied to clipboard
var keyExchangeGroups: KeyExchangeGroups

The key-exchange groups, most preferred first, and the groups a client sends key shares for (RFC 9846 sections 4.3.7 and 4.3.8); default KeyExchangeGroups.Default: X25519MLKEM768, X25519, P-256, X448, P-384, P-521, a client sending shares for the first two. A server picks by its own order, a group the client sent a share for first; see KeyExchangeGroups for the HelloRetryRequest and the handshake_failure a mismatch costs. build throws TlsException.Config for a group the OpenSSL in use does not provide, for key shares on a server, and for TlsVersions.Tls12And13 with no elliptic curve in the list (TLS 1.2 has no hybrid). In TLS 1.2 the list also limits the curves of the peer's ECDSA certificate (RFC 8422 section 5.1): a client without KeyExchangeGroups.SECP256R1 refuses a P-256 server certificate (handshake_failure), a server without it a P-256 client certificate (illegal_parameter).

sniSelector
Link copied to clipboard
var sniSelector: suspend (ClientHelloInfo) -> ServerTlsOverride??

Server, over TCP and QUIC alike: called with the ClientHello while the handshake is paused, it chooses this connection's identity and settings. Null from it with SNI present ends the handshake with unrecognized_name (RFC 6066 section 3); without SNI the default identity is used, and without one either the handshake ends with missing_extension (RFC 9846 section 9.2). A session ticket resumes only under the server name and the certificate it was issued under, so a ticket of one identity never resumes under another (RFC 6066 section 3, RFC 9846 section 4.7.1). On QUIC the selector runs off the connection's loop; an override's ServerTlsOverride.alpn must still suit QUIC (non-empty), and one with client certificates gets no 0-RTT and no tickets (0-RTT with client certificates is not supported). An exception from it, or an override build would refuse, ends that handshake (TCP: with the exception; QUIC: with internal_error). Default null.

var trust: TrustConfig

How the peer is trusted; default TrustConfig.Platform, the OS trust store. A client checks the server with it; a server checks client certificates with it when clientAuth is not ClientAuth.None, and then v1 accepts only TrustConfig.AnchoredCa or TrustConfig.ReloadableCa (a bundle that rotates at run time), optionally inside TrustConfig.Pinned (ADR-0012); a client refuses a ReloadableCa. The host name check is never disabled.

build
Link copied to clipboard
fun build(): TlsConfig

Validates the settings and returns an immutable TlsConfig. Throws TlsException.Config for an ALPN entry that is empty or longer than 255 bytes (UTF-8) or a list longer than 255 bytes on the wire, a server without identity or sniSelector, clientAuth on a client or without an AnchoredCa or ReloadableCa trust, a ReloadableCa on a client, an alpnFallback on a client, h3 or not 1..255 bytes, keyExchangeGroups this OpenSSL lacks, key shares on a server or groups without one TLS 1.2 can use under TlsVersions.Tls12And13, and an invalid serverName or ExpectedName. Transport-specific rules (QUIC) are checked when the configuration is used.
