data object UnknownRevocationStatus : VerifyReason

The revocation status could not be determined and the verifier requires it; alert unknown_ca (48). Reported by the platform verifier when it says so (JVM PKIX UNDETERMINED_REVOCATION_STATUS, Apple errSecIncompleteCertRevocationCheck), by a CertificateVerifier, and by ksl's own verifier for a configured CRL that expired, is not valid yet or does not verify, and when RevocationPolicy.RequireStapled or a must-staple certificate (RFC 7633) found no stapled response or one that says "unknown" (then the alert sent is bad_certificate_status_response (113), RFC 6066 section 8).

WeakKey
Link copied to clipboard
data object WeakKey : VerifyReason

A key in the peer's chain is below OpenSSL security level 2, 112 bits (RSA under 2048 bits, an elliptic curve under 224 bits); alert bad_certificate (42). Checked under every TrustConfig (the JDK, Android and Windows verifiers accept 1024-bit RSA): on OpenSSL's own path (TrustConfig.AnchoredCa, Platform on Linux) by OpenSSL on the path it built; under TrustConfig.Platform elsewhere by ksl after the platform's yes, on the path the platform built (a certificate the peer sent that the platform did not use does not count), or on the presented chain when the platform does not say its path; under TrustConfig.Custom and TrustConfig.Tofu by ksl before the verifier or the store is asked, on every certificate the peer sent that is reachable from the leaf through issuers whose key verifies the signature (stricter than OpenSSL for a certificate sent above the anchor the application trusts). The trust anchor's key counts everywhere.

WeakSignature
Link copied to clipboard
data object WeakSignature : VerifyReason

A certificate in the peer's chain is signed with a digest below OpenSSL security level 2, 112 bits: SHA-1 or MD5 (RFC 9846 section 4.5.1.3: MD5 MUST and SHA-1 SHOULD be refused); alert bad_certificate (42). The trust anchor's signature is not checked on a path OpenSSL or the platform built, nor, on a presented chain, the own signature of a self-signed certificate (one that verifies under its own key): they begin the path. Checked where WeakKey is.

Properties

alertCode
Link copied to clipboard
val VerifyReason.alertCode: Int

The TLS alert code that TlsException.Verify produces (RFC 9846 section 6.2) when the reason comes from a verifier that chooses the alert (a CertificateVerifier, the platform, pins). Where ksl decides, the alert sent follows OpenSSL: a failed stapled OCSP check is always bad_certificate_status_response (113, RFC 6066 section 8), whatever the reason (VerifyReason.Revoked, VerifyReason.InvalidStatusResponse, VerifyReason.UnknownRevocationStatus) and also with TlsConfig.genericAlerts; a configured CRL gives the alert OpenSSL maps its error to (ssl_x509err2alert): certificate_revoked (44) for a revoked certificate, certificate_expired (45) for an expired CRL, bad_certificate (42) for a CRL not valid yet, with a bad time field or a signature that does not decrypt, decrypt_error (51) for a CRL signature that does not verify, unknown_ca (48) when no usable CRL or CRL issuer is found, and certificate_unknown (46) for a CRL of another scope, an issuer without cRLSign or an unknown critical CRL extension.
