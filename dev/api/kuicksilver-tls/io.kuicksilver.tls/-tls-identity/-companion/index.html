object Companion(source)

Factories: fromPem, fromDer, and on the JVM fromKeyStore and fromPkcs12. Each throws TlsException.Config on bad input. reloadable wraps one for certificate rotation.

fromKeyStore
Link copied to clipboard
fun TlsIdentity.Companion.fromKeyStore(keyStore: KeyStore, alias: String, password: CharArray): TlsIdentity.InMemory

JVM: import an identity from a KeyStore (migration path from Ktor's sslConnector { keyStore }); the key is exported as PKCS#8 and that copy is zeroed after import. The KeyStore's own PrivateKey objects cannot be wiped and stay on the heap while the key store lives (and as garbage after); use fromPem or fromDer when a heap dump must not contain the key.

fromPem
Link copied to clipboard
fun fromPem(chainPem: String, keyPem: CharArray, password: CharArray? = null): TlsIdentity.InMemory

PEM chain (leaf first) + PKCS#8 PEM key as a CharArray, zeroed after import; encrypted keys are not supported in v1. The key is decoded straight from the array (no String of it is made) and every decoded block is wiped, on failure too; a String the caller read the key into is outside the library's reach.

fun TlsIdentity.Companion.fromPkcs12(bytes: ByteArray, password: CharArray): TlsIdentity.InMemory

JVM: PKCS#12 bundles through the JDK keystore provider. The JDK decrypts the key into objects that cannot be wiped and that stay on the heap as garbage until collected (threat model 3.7); use fromPem or fromDer when a heap dump must not contain the key.
