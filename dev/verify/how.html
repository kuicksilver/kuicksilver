The process

Every change goes through the same steps; each link goes to the section of the process document that describes it.

  1. A test that fails before the fix
  2. Review of the code against the RFC text
  3. The RFC compliance matrix and the threat model
  4. Integration and the local gate on every platform
  5. Hosted CI (the results on these pages)
  6. Before a release: soak tests, fuzzing, benchmarks
  7. The release

To check that the artifacts you download are the ones released, and that the native libraries are what the tagged sources build, see docs/verifying.md

The process document is the single source; this page only links to it: docs/process.md
