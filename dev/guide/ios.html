Kuicksilver on iOS

What this page is for. It is for an iOS app developer who wants to add Kuicksilver, through Kotlin Multiplatform or SwiftPM: what to depend on, how it links, what Apple's privacy manifest and networking rules mean for it, and how to check the size and the build.

Before you start

  • Kotlin 2.4.x with the targets iosArm64 and iosSimulatorArm64 (Kotlin/Native needs Kotlin 2.4.x, Kotlin version), or a Swift-only app; iOS 15 or newer.
  • Kuicksilver's binaries are built with Xcode 27.0; apps on Kotlin 2.4.20 may build with Xcode 26.4 or 27.0 (Platforms).
  • Dependency: io.kuicksilver:kuicksilver-http3:0.3.0 or newer (or -quic, -ktor-client) for Kotlin Multiplatform. For Swift, the Swift package kuicksilver-swift (Kuicksilver.xcframework, attached to every GitHub release from 0.3.0).

Minimal example. The Gradle setup is in Kotlin Multiplatform: klibs and one framework, the SwiftPM one in Swift only, and a running app in samples/ios.

Kuicksilver runs on iOS through Kotlin/Native (iosArm64, iosSimulatorArm64). OpenSSL 3.5 and the ksl C shim are linked statically into your app with every OpenSSL symbol renamed to ksl_ossl_* (ADR-0007), so another OpenSSL or BoringSSL in the same app does not clash with it. The QUIC socket is the accelerated ksl socket (ECN, DF; no GSO/GRO on Darwin). Certificates are checked by SecTrust when you use TrustConfig.Platform.

The working example is samples/ios: a SwiftUI app over a small Kotlin facade, with HTTP/3 GET, a raw QUIC echo with an RTT and path-event log, and a server mode advertised over Bonjour.

Choosing how to consume it

Your app Use What you ship

Kotlin Multiplatform: klibs and one framework

Depend on the Kuicksilver modules from your shared module like any KMP library. The klibs carry the prefixed OpenSSL and libksl as static libraries; Kotlin/Native links them into the framework your app already builds:

kotlin {
    listOf(iosArm64(), iosSimulatorArm64()).forEach {
        it.binaries.framework { baseName = "Shared"; isStatic = true }
    }
    sourceSets.commonMain.dependencies {
        implementation("io.kuicksilver:kuicksilver-http3:0.3.0")   // or -quic, -ktor-client
    }
}

Hook the framework into Xcode the KMP way (direct integration): a Run Script phase before Compile Sources that runs ./gradlew :shared:embedAndSignAppleFrameworkForXcode, User Script Sandboxing off (ENABLE_USER_SCRIPT_SANDBOXING = NO), and FRAMEWORK_SEARCH_PATHS = $(SRCROOT)/shared/build/xcode-frameworks/$(CONFIGURATION)/$(SDK_NAME) with OTHER_LDFLAGS = -framework Shared. samples/ios/Config/Project.xcconfig and build-kotlin-framework.sh show the complete setup.

One Kotlin/Native framework per app. Every Kotlin/Native framework carries its own Kotlin runtime, stdlib and copies of every library it uses: two frameworks mean two garbage collectors, two copies of Kuicksilver (and of OpenSSL) and types that do not cross between them (a QuicConnection from one is not one in the other). Put everything Kotlin into one umbrella framework. In particular do not combine your own KMP framework with Kuicksilver.xcframework: depend on the klibs instead.

Expose a thin facade to Swift rather than the library API: Kotlin suspend functions become Swift async functions or completion handlers in the generated header, but Flow, ByteReadChannel and Kotlin generics translate poorly. The sample's SampleFacade runs every operation on a background dispatcher and calls back on the main thread with (result, error), with no SKIE or other compiler plugin.

Swift only: Kuicksilver.xcframework and SwiftPM

The Swift package is kuicksilver/kuicksilver-swift, a small repository with no source code: its Package.swift declares one binary target, Kuicksilver.xcframework.zip of this repository's GitHub release, with its checksum, and each of its tags (0.3.0, ...) is made by the release of that version. Add it in Xcode (File → Add Package Dependencies…, the URL https://github.com/kuicksilver/kuicksilver-swift, Up to Next Minor Version from 0.3.0: before 1.0 a minor version may break the API, Stability levels) or in your own Package.swift:

dependencies: [
    .package(url: "https://github.com/kuicksilver/kuicksilver-swift", .upToNextMinor(from: "0.3.0")),
],
targets: [
    .target(name: "App", dependencies: [.product(name: "Kuicksilver", package: "kuicksilver-swift")]),
]

SwiftPM resolves the tag 0.3.0 of that repository, reads its Package.swift and downloads https://github.com/kuicksilver/kuicksilver/releases/download/v0.3.0/Kuicksilver.xcframework.zip, which it accepts only if its SHA-256 is the checksum there. The release signs the zip with the release key (.asc next to it) and lists it in the build provenance; tools/verify/verify-release.sh checks both and that the Swift package's Package.swift names exactly that zip (Verifying a release). A release candidate is tagged too (0.3.0-rc1); SwiftPM never picks a prerelease for a version range, so name it with exact: "0.3.0-rc1". Swift then calls the API directly (import Kuicksilver; suspend functions are async); KuicksilverInfo.VERSION names the version you got.

The framework is dynamic, so its dSYMs travel with it and Apple finds its privacy manifest in its own bundle; the licences (Kuicksilver's and OpenSSL's, both Apache-2.0) are in the framework too, so they ship with your app:

Kuicksilver.xcframework
  ios-arm64/Kuicksilver.framework (+ PrivacyInfo.xcprivacy, LICENSE, NOTICE, licenses/)   ios-arm64/dSYMs/…
  ios-arm64-simulator/…                                                                ios-arm64-simulator/dSYMs/…

It is the small umbrella module samples/ios/kuicksilver-swift, which exports the public API of kuicksilver-tls, kuicksilver-quic and kuicksilver-http3 through the Kotlin XCFramework DSL. To build it yourself (an unreleased commit, or to compare with the release asset), from a checkout:

tools/release/xcframework.sh 0.3.0
#   build/release/Kuicksilver.xcframework.zip and its SwiftPM checksum (what `swift package compute-checksum` prints)

The zip is reproducible on the same toolchain: the klibs, the symbols and the dSYMs name the sources relative to the checkout, the zip has fixed timestamps and order, and the slices are listed in a fixed order, so the same commit and Xcode give the same checksum in any checkout directory. Only the native libraries inside are compared with an independent rebuild by verify-release.sh (Which native libraries are reproducible); the Kotlin code is not.

Privacy manifest

Apple requires a privacy manifest that declares every "required reason" API an app or SDK uses. Kuicksilver's is kuicksilver-native/apple/PrivacyInfo.xcprivacy: no tracking, no collected data, one API category.

Category Symbols in a Release arm64 link Where from Reason
File timestamp stat, fstat, lstat OpenSSL's file loaders (X509_STORE_load_file/path, which libksl links for a file-based trust store; conf_def.c, ssl_cert.c, file_store.c), the /dev/urandom fallback of rand_unix.c, and fstat in the key log file check when you enable keylog C617.1: metadata of files inside the app container that the app points Kuicksilver at; Kuicksilver reads the file type, owner and link count, never sends anything
System boot time none Kotlin/Native measures time with libc++ steady_clock and gettimeofday, not mach_absolute_time or systemUptime not declared
Disk space, active keyboards, user defaults none not declared

sysctlbyname (OpenSSL reads the hw.optional.arm.* CPU features) is not on Apple's list. Check your own build with tools/check/ios-private-api.py (Checks): it prints a required-reason line per category it finds. Debug builds of a Kotlin framework import far more (getattrlist, clock_gettime, …) because they link the per-library caches with every platform binding; only the Release link is what you ship.

How to include it:

  • Kuicksilver.xcframework (the Swift package) carries the file in each framework; nothing to do.
  • A KMP app (Kuicksilver is linked statically into your framework, and a static framework has no bundle of its own): merge the entries into your app's PrivacyInfo.xcprivacy. The Maven artifacts (klibs) do not carry the file, so you need nothing from this repository: the complete manifest, with the same entries, is App Store: Templates, 6. Privacy manifest, ready to paste; the repository's file at the tag of the version you use (v0.3.0, ...) is the reference. If your app has no manifest, save that template as PrivacyInfo.xcprivacy in the app target (Copy Bundle Resources), as the sample does with Kuicksilver's file. If you have one, add the NSPrivacyAccessedAPICategoryFileTimestamp entry with C617.1 (keep your own reasons next to it).
  • If your app persists TOFU pins in user defaults or reads timestamps for its own purposes, that is your code's use: declare it with your own reason.

Export compliance

Kuicksilver contains encryption (OpenSSL: TLS 1.3, AES-GCM, ChaCha20-Poly1305, X25519, ML-KEM) and implements it in the app rather than using the operating system's. Apple's guidance is that encryption built into the OS (for example HTTPS through URLSession) is typically exempt from export documentation, and other encryption is not. The sample therefore sets ITSAppUsesNonExemptEncryption to true:

  • Under the U.S. Export Administration Regulations, an app that uses standard cryptography to secure its own communication is usually a mass-market item exported under License Exception ENC, 15 CFR 740.17(b)(1), and classified 5D992.c after self-classification. Since the 2021 amendment, the annual self-classification report of 740.17(e)(3) covers mass-market components and certain executable software rather than end-user apps, but the recordkeeping of part 762 applies.
  • App Store Connect asks about encryption for every build unless the Info.plist answers it, and may ask for documentation (then add ITSEncryptionExportComplianceCode), including a declaration for distribution in France.
  • The step-by-step version, with the App Store Connect questions, Info.plist and review-note templates, is app-store.md.
  • The classification and the answers are the app owner's decision and responsibility, not the library's, and this section is not legal advice. Changing what the app encrypts (for example adding end-to-end encryption of user data on top) can change the answer.

Networking rules on iOS

  • App Transport Security does not apply. ATS governs URLSession and other URL-loading APIs. Kuicksilver opens its own UDP and TCP sockets, so NSAppTransportSecurity settings neither allow nor block it. Your TLS policy is Kuicksilver's: TrustConfig.Platform (SecTrust, the system and MDM roots), pins, or a private CA; host names are always checked.
  • Local network permission. Talking to a device on the LAN (a server on another phone, an echo peer, a printer) triggers the iOS local network prompt. Declare NSLocalNetworkUsageDescription, and NSBonjourServices for every service type you browse or advertise (_kuicksilver._udp in the sample). Loopback and Internet traffic need neither.
  • Servers are foreground only. A QUIC server on iOS works (bind :: for dual-stack), but the system suspends the app, and with it the socket, shortly after it leaves the screen. Use loops = 1.
  • IPv6-only networks. App Review tests on a NAT64 network. Bind :: and connect by host name: the endpoint resolves the name once, and on NAT64 the system resolver synthesises an IPv6 address for an IPv4-only host. Do not hard-code IPv4 literals.
  • Network changes. A QUIC connection survives a move to another socket (QuicConnection.migrate, rebind). QuicConnection.followDefaultNetwork(scope) (experimental) follows the default network automatically (Wi-Fi to cellular and back) through one shared NWPathMonitor, and also replaces a socket iOS reclaimed while the app was suspended (QUIC: Network changes). The sample's echo screen has a "Follow the default network" toggle for it and a manual Rebind button. For HttpClient(Kuicksilver), http3 { connectionMigration = Http3ConnectionMigration.followDefaultNetwork() } (experimental, off by default) does the same for every pooled HTTP/3 connection (Ktor: Connection migration).

Checks

The project runs these scripts on samples/ios before a release, so they need a checkout of this repository; their results are below. For your own app you need only tools/check/ios-private-api.py, a single Python 3 file that needs a full Xcode (the iOS SDK and nm; the Command Line Tools alone have no iOS SDK): take it from the tag of the version you use (https://raw.githubusercontent.com/kuicksilver/kuicksilver/v<version>/tools/check/ios-private-api.py) and run it on your Release binary, python3 ios-private-api.py "$(xcrun --sdk iphoneos --show-sdk-path)" <your app's executable>. It lists any symbol that no public SDK library exports and the required-reason API categories it finds, which the privacy manifest must declare. Your app's own size impact comes from its linker map (LD_GENERATE_MAP_FILE = YES), as in Size.

Device checklist

The simulator shares the Mac's network stack, so these need an iPhone. Open samples/ios/KuicksilverSample.xcodeproj, select your team in Signing & Capabilities (a free Apple ID works; if the bundle ID is taken, change KUICKSILVER_BUNDLE_PREFIX in samples/ios/Config/Project.xcconfig), pick the phone and press Run. For a server and a client, run the app on two devices, or point the echo screen at samples/realtime-telemetry-style peers on a Mac.

  1. Wi-Fi and cellular, separately: HTTP/3 GET of a public site with System trust; echo to a server on the LAN (Wi-Fi only).
  2. Handover under load: an echo session with 300 rounds every 250 ms, then walk out of Wi-Fi range (or turn Wi-Fi off), once with "Follow the default network" on and once with Rebind by hand; the log must show path changed without a new handshake.
  3. Backgrounding: start an echo session, background the app for 5 s, 60 s and 5 min, return; note whether the session survives (the idle timeout is 30 s) and that a new one works.
  4. Low Power Mode: repeat 1 and 2.
  5. IPv6-only through NAT64: share the Mac's connection over Wi-Fi with "Create NAT64 Network" (System Settings > General > Sharing > Internet Sharing, Option-click for the NAT64 choice); HTTP/3 GET of an IPv4-only host name must work.
  6. Captive portal: join a network before signing in; requests must fail cleanly (a handshake timeout, no hang).
  7. VPN: with a VPN on, HTTP/3 and echo; the smaller MTU must not stall the transfer (PMTUD falls back to 1200).
  8. iCloud Private Relay: on; Private Relay covers Safari, DNS and unencrypted HTTP, not an app's own QUIC, so the results must match 1 (name resolution may take a different route).
  9. LAN server: Server tab, Start; accept the local network prompt; from another phone, echo to the shown address with Sample CA trust, and open the https:// address with the HTTP/3 screen. The service is visible as _kuicksilver._udp to a Bonjour browser.

Before relying on a release on devices, run at least items 1, 2, 3 and 5.
